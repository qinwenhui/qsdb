## 四、拦路虎（按"性质"分类，不是按次数）

### 4.1 ⬜ `least` / `greatest`（21 + 10）——**trivial，建议第一件事就补**

逐行取多参的最小/最大值，NULL 语义按 Spark（忽略 NULL，全 NULL 则 NULL）。
实现 ≈ 20 行（照 `coalesce` 那条路：绑定期算公共超类型 + 执行期逐行比较）。

### 4.2 ❌ `stack(n, k1, v1, k2, v2, …)`（52）——**列转行**

真实用法（清单 2437 行附近）：

```sql
SELECT …, stack(6, '跨区跨省点对点中长期交易合约电量', CAST(ENERGY AS decimal(38,11)),
                   '跨区跨省点对点中长期交易合约电价', CAST(PRICE AS decimal(38,11)), …)
FROM …
```

语义：**每个输入行展开成 n 行**，第 i 行取第 i 组 `(key, value)` ⇒ 输出行数 ×n。

**难点**：它是**行数会变的生成器**（`Generated`/`LateralView` 一类），不是逐行标量函数
—— 要动执行层的"一行进、多行出"能力，且要与 `SELECT` 里其它列一起对齐。
**这一条要单独出设计稿**，别顺手做。

### 4.3 ❌ `PIVOT ( … FOR col IN ( … ) )`（54）——**数据透视**

Spark 的透视子句（清单 2448 行附近）：`FROM (子查询) PIVOT (sum(x) FOR col IN ('a','b','c'))`
⇒ **列名由数据决定**（行转列）。

**难点**：**输出 schema 依赖数据**（`IN (...)` 里的值列表；Spark 还支持子查询动态取）
⇒ 与我们"绑定期定 schema"的模型正面冲突。**这条也要单独出设计稿**，
而且要**先明确口径**（只支持字面量 `IN` 列表？还是要动态？）。

### 4.4 ❌ `库.表` 限定名（266 次，全是 `js_produce.…`）——**是个"设计决定"，不是"没实现"**

本仓**显式拒**限定名（`qualified names (db.table) not supported yet; single database in use`，
见 `SQL支持面.md` §〇）。但这里有个**真问题要拍板**：

- 语料里的 266 次**全是同一个库**（`js_produce.`）⇒ 在我们单库模型下**没有歧义**
  （`js_produce.t_x` 只可能指 `t_x`）；
- 那么**"接受并忽略库前缀"**算不算"静默"？本仓纪律是"不静默兜底"，
  但这里忽略的是**没有歧义的信息**，与"拼错不报错"不是一回事。

⇒ **建议按这个口径**：**接受限定名，但要求前缀必须等于当前库名（或 `default`）**，
否则显式拒 —— 既让 Spark 的 SQL 原样能跑，又不会把"指到另一个库"的意图悄悄吞掉。
**这条要用户拍板**（它影响整个语料能不能"原文照跑"）。

## 五、落地方法（照本仓纪律来）

1. **抽取**：按 `### [L?-??] 任务名` 把 154 个 SQL 块切成一个个文件
   （一个任务一个 `.sql`，任务名进文件名）。
   ⚠️ **每个文件末尾必须有 `;`** —— `qsdb shell` 对**未以 `;` 结尾的语句静默丢弃**
   （2026-10-16 踩过，见 `进度与待办.md` §〇之五）。
2. **逐条跑**（`.14`）：`qsdb shell --path /home/qctc/qsdb-js < 任务.sql`
3. **三分类**（每条都要落到其中一类，**不许"跑不过就跳过"**）：
   - ① **直接过** → 记耗时 + 结果行数；
   - ② **补能力后过** → 记缺什么，补完再跑（`least`/`greatest` 属于这类）；
   - ③ **确实不支持** → 记进 §四（`pivot` / `stack`），并写清"为什么难"。
4. **值对账**（能跑的都要）：`.14` 上有**真 Spark 3.5.2**
   （`/opt/module/spark-3.5.2`）⇒ 同一批 SQL 两边跑、比**逐值聚合**
   （`count(*)` / `sum(dec)` 的定长小数文本 / min / max；⚠️ `uuid` 列跨引擎必然不同，排除）。
   口径与坑见记忆 `qsdb-real-table-testing`。
5. **⚠️ 先确认数据齐**：语料引用的是 `js_produce` 下的表；`/home/qctc/qsdb-js` 里已有
   那批迁过来的表 ✓（71 张 + 几张后补的）。**开工第一步是先跑一遍"表都在吗"**，
   缺哪张就补迁哪张。

## 七、验收口径

**"能跑"= 跑通 + 结果对**，两者缺一不算：

- 跑通：不报错、返回行数合理；
- 结果对：与 `.14` 上的真 Spark **逐值对账**（同一批 SQL、同一份数据）；
- **不许"跑不过就跳过"** —— 每条 SQL 必须落到 §五 的三分类之一，
  ③ 类必须写清"为什么不支持"，而不是一句"不支持"。
