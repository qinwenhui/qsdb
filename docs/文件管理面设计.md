# 文件管理面设计（二十批）

> Studio 需求：像浏览文件目录一样浏览/查看/删除/导出**原始 parquet 段文件**，
> 并能看到"这个文件属于哪张表的哪个分区"。QSDB 的存储布局是人类可导航的
> `<根>/<库名>/<表>/<分区>/seg_*.parquet`——**路径本身就是语义**，别的数据库
> 做文件浏览器是猎奇，我们做是本命。本设计把已有的单文件下载（`GET /files`）
> 补成完整的文件管理面。

## 一、端点总览

| 端点 | 方法 | 权限 | 作用 |
|---|---|---|---|
| `/api/v1/files/list?dir=` | GET | 读授权（见 §二） | 列目录一层 |
| `/api/v1/files/detail?path=` | GET | 读授权 | 单文件/目录详情（段带列统计） |
| `/api/v1/files`（已有） | GET | ~~admin~~ → 读授权 | 单文件流式下载（**放宽**，见 §二.3） |
| `/api/v1/files/trash?path=` | POST | **admin 专属** | 引用检查 + 移入 `_trash`（见 §三） |

路径寻址与既有 `/files` 完全同款：`<挂载名>/<存储根相对路径>`；`default` **不剥**
（存储布局 `<根>/<库名>/…`，default 库的文件历史上就以 `default/…` 寻址）。
三个新端点与下载共用同一个路径解析助手（`files_resolve`），行为不会分叉。

内部路径 `_trash/` / `_spill/` / `_filecache/` 与从前一样**全员 403**；
库根层以 `_` 开头的目录（`_catalog` 等——用户表就在里面）在列表里**隐藏**
（不回显存在性，和下载的 403 口径一致）。

## 二、权限模型

**读授权 = 对路径归属库有任意角色；删除恒为 admin。**

1. **归属库判定**：路径首段是挂载名（≠`default`）→ 该挂载；否则 → `default`。
   判定用 `resolved_role_for(user, 归属库)` **现查** grants（与 SQL 面"改了立即生效"同款）。
2. **非 admin 列根目录 = 虚拟视图**：不回真实文件系统根，只回自己**有 grant 的挂载名**
   （type=dir）。admin 列根 = 真实目录 + `mounts` 清单。Studio 侧栏从 `mounts` 起步。
3. **下载放宽**：`/files` 从 admin 专属放宽为读授权。理由：对库有 reader 角色的用户
   本来就能 `SELECT` 全部数据——段文件里不会有 SELECT 拿不到的东西；而"能浏览却
   不能打开"是假权限。qsdb-sync 走 admin token，不受影响。

身份判定与 `/sessions` 可见性同源（`authenticate_identity`）：
401（未认证/吊销）与 403（无 grant）分开，客户端动作不同（重登 vs 找管理员授权）。

## 三、删除安全（红线）

**绝不允许裸删。** 段文件被 manifest 引用着——直接删 = 表读取永久损坏
（manifest 是唯一真值，查询会报 open failed）。`POST /files/trash` 的完整边界：

1. **只收段文件**：目标必须是 `seg_*.parquet` 文件。manifest / partitions.idx /
   table.json / 目录 / 其它文件 → 400 `INVALID_ARGUMENT`（这些是元数据，删了就是毁表）。
2. **引用检查 + 分区锁**：持分区锁（`{分区目录}/.lock`，与写路径同一把）内
   重读兄弟 manifest：
   - `file_name` 在 `manifest.segments` 里 → **409 `SEGMENT_REFERENCED`**（新码，
     SQLState 55006 object_in_use），文案指路正确动作
     （`DELETE WHERE <分区>` / `INSERT OVERWRITE`）；
   - 不在（GC 遗留 / 崩溃残留 / 分区已重建）→ 孤儿，`move_to_trash` 进 `_trash`。
   锁内**重查**而非锁外查完带进来：检查与移动之间若有写者提交新 manifest，
   锁保证了串行。
3. **回收站而非 unlink**：进 `_trash/{ts}/`（带 `.qsdb_src` 来源标记），
   静默期内可用 `admin trash restore` 捞回。文件级删除永远是可撤销的两步，
   不是一步到黑洞。
4. **远端库显式拒绝**：`move_to_trash` 是本地 fs 原语，远端 Store → 501
   `UNSUPPORTED`（绝不静默假装删了）。list/detail 走 `Store::read_dir`/`stat`，
   本地远端通吃。

"看回收站/恢复/清空"已有 CLI（`admin trash …`），本期不 HTTP 化——等 Studio
真需要时再加，避免为一个没有消费方的面扩契约。

## 四、响应形状

### `GET /files/list?dir=`（dir 缺省 = 根）

```json
{
  "dir": "default/settle_result/dt=2026-01-01",
  "mounts": [{"name": "default", "isDefault": true}, {"name": "settle", "isDefault": false}],
  "count": 2,
  "entries": [
    {"name": "manifest.postcard", "type": "file", "size": 812, "modifiedMs": 1760000000000},
    {"name": "seg_01a14ed9….parquet", "type": "file", "size": 2387104, "modifiedMs": 1760000000000,
     "segment": {"referenced": true, "rows": 100000, "bytes": 2387104, "createdAtMs": 1760000000000}}
  ]
}
```

- 目录排前、名字序；`type`: `"dir"` | `"file"`；`size`/`modifiedMs` 仅文件有。
- **段文件免读文件就带归属信息**：同目录所有段共享一份 manifest，读一次
  全标好（`referenced`/`rows`/`bytes`/`createdAtMs`）。manifest 读不到时
  `referenced: null`（**未知 ≠ 未引用**——null 不给删除按钮亮绿灯）。
- `mounts` 恒回（按调用方可见性过滤）：Studio 不用再调 `/databases` 拼侧栏。

### `GET /files/detail?path=`

```json
{
  "path": "default/t/dt=2026-01-01/seg_x.parquet",
  "name": "seg_x.parquet", "type": "file", "kind": "segment",
  "size": 2387104, "modifiedMs": 1760000000000,
  "db": "default", "table": "t", "partition": "dt=2026-01-01",
  "segment": {
    "referenced": true, "rows": 100000, "bytes": 2387104,
    "createdAtMs": 1760000000000, "generation": 7,
    "columns": [{"name": "a", "min": "1", "max": "99999", "nullCount": 0}]
  },
  "readSql": "SELECT * FROM read_parquet('D:\\data\\default\\t\\dt=2026-01-01\\seg_x.parquet')"
}
```

- `kind`: `segment` | `manifest` | `index` | `tabledef` | `other`（按文件名判）。
- 段：`columns` 直接来自 manifest 的 `SegmentEntry.column_stats`（min/max 走
  `Literal::Display`，NULL → `null`）——**不读 parquet 就能展示"这个段里有什么"**，
  这是通用文件浏览器给不了的信息。
- manifest 文件本身可 detail：回 `generation`/`rows`/`segments`/`partitionValues`。
- `tabledef`（table.json）解析成功时内嵌 `"tableDef": {…}` 原样 JSON。
- `readSql` = 服务端拼好的单文件查询（本地库才有此字段）——Studio"预览此文件"
  按钮直接拿去走查询面，权限由查询面自己管。
- 目录也可 detail：`type:"dir"` + 子条目计数（文件数/目录数/合计字节，浅层）。

### `POST /files/trash?path=`

```json
{"trashed": true, "path": "default/t/dt=2099-01-01/seg_orphan.parquet",
 "note": "moved to _trash; recoverable via `admin trash restore` within the grace period"}
```

失败：409 `SEGMENT_REFERENCED`（被引用）/ 400（非段文件）/ 403（非 admin）/
404（不存在）/ 503 `IO_ERROR`（Windows 句柄占用，可重试）。

## 五、错误码

新增一个（目录只增不改）：

| code | http | retry | category | sqlState | 语义 |
|---|---|---|---|---|---|
| `SEGMENT_REFERENCED` | 409 | no | resource | `55006` | 段被存活 manifest 引用，拒绝进回收站 |

不借用现有 409 码：`WRITE_CONFLICT` 是"并发写冲突，重读再试"，这里是
"这个对象正被引用，换个动作"——语义相反（一个该重试、一个不该），混用会误导驱动。

## 六、明确不做（本期边界）

- **不做**目录级 trash（删整个分区目录请走 `DELETE WHERE` / 清空分区——那才是
  会更新 manifest 的正确路径）；
- **不做**回收站 HTTP 面（CLI 已覆盖）；
- **不做**文件改名/移动/上传（库是引擎的，不是文件柜——外部写入走 import/COPY）；
- **不做**非 admin 的 `_trash` 浏览。

## 七、验收

1. admin 浏览：根列表 → 表目录 → 分区目录，段文件带 `referenced:true` + 行数字节；
   detail 出列统计与 `readSql`。
2. 引用段 trash → 409 `SEGMENT_REFERENCED`；复制出的孤儿段 trash → 200，
   `_trash` 里有货、原位消失。
3. 权限：settle 读者能 list/detail/下载 settle 文件、摸 default → 403；
   trash 恒 403（非 admin）；无 grant 用户 list → 403。
4. 非空目录列表、非 admin 虚拟根、manifest/tabledef 详情不炸。
5. 既有 19 基准 + 154 语料 + 全部回归原样（读路径零改动——只有 download 的
   鉴权行换了个助手）。

## 八、落地注记（2026-10-19 全落地）

- 实现与设计逐条一致（list/detail/trash + download 放宽 + `SEGMENT_REFERENCED`
  新码，码表已同步 `docs/error-codes.md`——漂移测试逐字对账）。
- 途中撞出的两个**存量语义**（未改，测试注释里已锚定）：
  1. **USE 到别的库**先对**当前**库判权——只授了 settle 的用户 `USE settle` 会 403，
     得用限定名 `settle.t`（按目标库判权，M-B 路由）。文件面不受影响（自带归属库）。
  2. **DDL 恒 admin**：writer 也不能 `CREATE TABLE`（错误文案明说）。测试里
     settle 建表由 admin 限定名完成，writer 只做 INSERT。
- `readSql` 回程钉住：客户端拿 `read_sql` 真查一遍（Windows 反斜杠路径原样可用），
  读出的行数 == manifest 记的行数（`client_roundtrip.rs::files_浏览详情与回收站往返`）。
