# 客户端采纳设计 —— qsdb-client 接入会话 / 多库 / 结果护栏（2026-10-18，第十八批设计稿）

> **缘起**：十六批（多库·会话·grants）与十七批（结果护栏·流式）落的全是
> **server 面**；契约的两个 Rust 消费方里，本仓自带的 [`qsdb-client`](../crates/qsdb-client)
> 还停在"Basic 凭证 + 单库 + 无护栏覆盖"的旧面——**服务端建好的会话/授权/
> 多库语义，自己的客户端还不会用**。本稿定 Scope、形态与分期，与 qsdb-jdbc
> 的采纳清单（六项，见批次讨论记录）是同一批契约的两个消费方。
>
> **纪律**：薄客户端红线不动——**零网络依赖**（手写 HTTP/1.1）、默认不拉
> arrow；**只增不改**（`Auth::Basic` 逐位兼容，老代码零迁移）；显式优先于
> 静默（凭证错就是错，不静默降级匿名）。

## 二、设计

### 2.1 C1 会话登录（本批主体）

**形态定案**：`Auth` 枚举**保持三态不变**（Basic 的"每请求带、零状态"是它对
匿名/静态场景的正确形态，不动）。会话是**另一种生命周期**，走独立入口：

```rust
impl Client {
    /// Basic 凭证换取**进程态会话**：login → token+sessionId 存进 Client。
    /// 之后的请求自动带 `Bearer <token>`；撞 `SESSION_REVOKED` 自动重登。
    pub fn login(&mut self, user: &str, password: &str) -> Result<SessionInfo>;
    /// 会话信息（登录后可查；grants 供调用方自查，不用撞 403 试探）。
    pub fn session(&self) -> Option<&SessionInfo>;
    /// 设会话默认库（SQL `USE` 的 REST 落点；库名按服务端挂载表校验）。
    pub fn use_database(&self, db: &str) -> Result<()>;
}
```

**四条语义定案**（写进 rustdoc 与契约，防各自理解）：

1. **凭证只存 `Mutex<AuthState>`**：`Client` 已是 `Send + Sync`（连接池是
   `Mutex<Option<BufConn>>`）；会话态同锁族。`Debug` **不回显凭证/token**
   （既有纪律，`Client` 的 Debug 只出 target）。
2. **重登互斥**：并发请求同时撞 `SESSION_REVOKED` 只允许一次 login 往返
   （双登 = 服务端多一个要踢的会话）。实现：重登在 `AuthState` 锁内完成，
   后到者发现 token 已换就复用。
3. **401 `SESSION_REVOKED` 后的重发分档**（与"POST 不透明重发"的既有纪律对齐）：
   - **读路径**（`query` 全通道）→ 自动重登 + **重发一次**。安全依据：服务端
     认证闸在执行**前**，401 = 语句从未运行（该假设写进 `docs/对接契约.md`
     §3.1，成为契约级承诺）；
   - **写路径**（`append` / SQL DML）→ **只重登、不重发**，返回
     `Error::Api`，错误文案告知"会话已被重置，请重试该操作"——调用方决定
     重试时机。宁可多一次手动重试，不赌"服务端一定没执行"。
   - **login 自身撞 401 `UNAUTHORIZED`** → `Err` 原样返回，**绝不降级匿名**
     （显式优先于静默；"凭证错装作没配凭证"是安全洞）。
4. **token 不持久化**：进程内存态（与服务端同生命周期语义——服务端重启即
   失效，重登零成本）。落盘 = 把长期凭证换成另一个长期凭证，白做。

`json.rs` 新增 `SessionInfo { session_id, user, role: Option<String>, grants, default_db }`
（login 响应 `sessionId`/`role`/`grants`/`defaultDb` 的直映射；`role: None`
= 白名单制用户当前无默认库授权，M-C 语义）。

### 2.2 C2 护栏覆盖：`QueryOptions.max_rows`

```rust
pub struct QueryOptions {
    // …format / timeout_ms / query_id / params 既有…
    /// 结果护栏的本请求覆盖（十七批 R1）→ body `"maxRows"`。
    /// **给出即接管护栏整体**（服务端行/体量两闸一并按此值放开或收紧）；
    /// `0` = 本请求不限。None = 服务器值说了算（缺省行为与从前逐位一致）。
    pub max_rows: Option<u64>,
}
```

**不做 `X-QSDB-Max-Rows` 头**：body 字段与头语义完全同位（body 优先），薄
客户端没有"要跟别的头拼优先级"的场景——一条路，不铺两条。

### 2.3 C3 多库

```rust
pub struct QueryOptions {
    // …
    /// 请求目标库（十六批 M-B）→ body `"database"`。**优先级最高**：
    /// 单段表名锚定在这里；未给 = 会话默认库 ?? "default"。
    pub database: Option<String>,
}
/// 挂载清单（admin 全列；非 admin 只列有 grant 的库——服务端不泄露库名）。
pub fn databases(&self) -> Result<Vec<DbInfo>>;   // {name, read_only}
```

`use_database` 归 C1（它本就是会话的属性）。`QueryOptions.database` 与
`use_database` 的分工照服务端语义：**显式字段 > 会话默认库**，文档里写死
优先级链，不造新词。

- `docs/客户端与嵌入方指南.md` 加"会话与授权""多库""大结果（护栏 + 流式

## 三、契约变更清单（只增不改）

| 项 | 变更 | 兼容性 |
|---|---|---|
| `Client` | 新增 `login` / `session` / `use_database` / `databases` | 纯增量；不调用则零差异 |
| `Auth` | **不变**（三态保留） | 老代码逐位兼容 |
| `QueryOptions` | 新增 `max_rows` / `database`（`None` 缺省） | 缺省行为与从前一字不差 |
| `json.rs` | 新增 `SessionInfo` / `DbInfo` | 纯增量 |
| `docs/对接契约.md` §3.1 | 增一句："**401 类错误 = 请求在认证闸被拒，语句从未执行**——客户端可安全地重登录后重发读请求" | 契约级承诺，服务端本就如此（认证先于执行），只是挑明 |

## 四、分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| **Ⅰ C1 会话** | `login`/`session`/`use_database` + SessionInfo + 重登分档 | 单测：login 往返、并发重登只登一次（两线程同时撞 REVOKED）、读路径自动重发、写路径不重发、凭证错不降级；契约：`client_roundtrip` 增"踢出后读自动恢复"用例（服务端 `DELETE /sessions/{id}` 踢人 → 下一条 query 透明成功） |
| **Ⅱ C2+C3** | `max_rows` / `database` / `databases()` + 文档（C4） | 单测：`max_rows` 覆盖往返（撞服务端护栏 → `Error::Api{code="RESULT_TOO_LARGE"}`）、`max_rows:0` 豁免、`database` 路由（双挂载 server）；`client_roundtrip` 全量回归 |

默认零行为变更（不 login / 不设新字段 = 与从前逐位一致）⇒ 既有测试全绿即回归关。

## 五、不做清单（v1 边界）

- **token 持久化 / 刷新**——进程内存态，服务端同语义（重启重登零成本）
- **写路径自动重发**——幂等红线（`append` 非幂等是本 crate 的第一设计约束）
- **会话池 / 多会话复用**——一个 Client 一个会话；要多会话就多建 Client（薄客户端不养池）
- **TLS**——既有定案不变（挂 TLS 终止代理）
- **Flight 通道**——jdbc 的 v2 预留，本客户端无此诉求
