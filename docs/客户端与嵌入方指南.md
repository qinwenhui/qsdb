# 客户端与嵌入方指南

> **这份文档补的是一个真实缺口**：生态文档里 jdbc / odbc / sync 三件套都齐，
> 但**最主要的两种消费方——"服务端 + 客户端"与"Rust 同进程嵌入"——反而没有文档**。
> 结果就是外部人（包括我们自己的 Rust 业务方）会以为"是不是得拉 jdbc"，
> 或者反过来"我只要个客户端，怎么把整个数据库拉过来了"。
>
> **最近更新：2026-10-15**

---

## 一、先选接入方式（一张表定）

| 你的情况 | 用什么 | 依赖什么 |
|---|---|---|
| **业务系统在别的机器上，QSDB 单独部署**（**默认路径**） | **HTTP API** + 薄客户端 | 客户端**只要 HTTP 与解码**，**不引内核** |
| Rust 服务与库**同进程**（嵌入式、边缘、单机分析） | `qsdb` crate 直接链 | 整个内核（arrow/parquet/执行器） |
| JVM 业务 / BI 工具 | qsdb-jdbc | 薄 HTTP |
| Excel / Tableau / PowerBI 等**既有 BI** | qsdb-odbc（开发中） | 薄 HTTP |
| **跨库/跨环境搬数据** | qsdb-sync | **引内核是对的**（见 §五） |

**一句话**：**"谁持有库"决定接入方式**。库在服务端 → 客户端薄；库在你进程里 → 直接链。

---

## 二、服务端路径（默认）：HTTP API

`qsdb-cli` 就是那个 server。**它是语言无关的**——Rust 客户端、jdbc、odbc 走的是同一套：

| 端点 | 用途 |
|---|---|
| `POST /api/v1/query` | `{"sql": …, "format": "ipc"\|"json"}` → **Arrow IPC 流** / JSON |
| `POST /api/v1/write?table=T&mode=append\|overwrite` | body = Arrow IPC 流 |
| `GET  /api/v1/tables` · `/tables/{t}/schema` · `/tables/{t}/partitions` | 元数据 |
| `GET  /api/v1/stats` | 库统计 |
| `GET  /api/v1/error-codes` | **运行期码表**（别把错误码硬编码进客户端） |

**两个批量通道**（大进大出，别走 SQL 结果面）：

- `docs/bulk-format.md` —— **列式**，大块导入导出；
- `docs/rows-format.md` —— **行式、驱动向**：行主序（零转置）、schema 外部提供、
  `row_count` 自带帧边界（攒够一拨就发，客户端内存 O(一块)）。
  `.14` 实测 5M 行**写 1.04s（与 IPC 持平、比列式 bulk 快 2×）**。

## 三、Rust 薄客户端：`qsdb-client`（**已落地**）

### 为什么要它

`qsdb` crate 的依赖里有 `arrow`/`parquet`/`sqlparser`/`postcard`/`rayon`/`sha2`…
**一个只想发 HTTP 的客户端会把这些全拉进编译图**。代价不是感觉，是实打实的：
编译时间、二进制体积、供应链面，以及**版本锁步**（客户端被迫跟着内核的
arrow/parquet 版本走）。

### 实际形态（`crates/qsdb-client`）

```
依赖：serde + serde_json            ← 默认**零网络依赖**（手写极简 HTTP/1.1）
feature "ipc" → + arrow             ← 要 Arrow 批才打开（会与内核版本锁步）

模块：error（传输层/语义层分档）· http（keep-alive、chunked、流式）·
      value（标签与值）· bulk（列式编解码）· rows（行式流式解码）·
      json（元数据与回执）· ipc（feature）
```

```rust
let c = qsdb_client::Client::connect("http://host:9430", Auth::Basic{ user, password })?;

// 会话（十六批面）：Basic 换进程态会话——踢人/审计归因/USE 默认库/grants 自查
let si = c.login(&user, &password)?;          // 之后撞 SESSION_REVOKED 自动重登
c.use_database("settle")?;                     // 会话默认库
c.databases()?;                                // 挂载清单（非 admin 只见有 grant 的库）

// 读：默认 `bulk`（列式、零拷贝、零依赖）。响应按 **Content-Type** 分派：
// DDL/DML 会回 JSON 回执 → `ResultSet` 是"载荷 + query id"，用 into_bulk() 取
let t = c.query("SELECT cat, count(*) FROM t GROUP BY cat")?.into_bulk()?;
for row in t.rows() { let (cat, n) = (row.get(0)?, row.get(1)?); }

// 大结果：流式（恒定内存，独占一条连接）。中途停止是**两段式**：
// 只调 cancel 停不住传输段（服务端先执行完、注销查询才开始传）——
// 发起时 with_query_id 报名，停止时先 cancel（执行段）再 s.abort()（传输段）
let mut s = c.query_stream("SELECT * FROM big", &Default::default())?;
while let Some(chunk) = s.next_chunk()? { for row in chunk.rows() { … } }

// 写：**批量装载**，不要逐行 INSERT（同量数据 81s → 2.18s，37×）
c.append("t", &[("id", vec![Some(1i64)].into()), ("name", Column::utf8([Some("a")]))])?;

// 元数据 / 取消 / 错误码目录
c.tables()?; c.schema("t")?; c.partitions("t")?; c.stats()?;
c.cancel(&id)?; c.error_codes()?;
```

### 与"规格"相比，三处**按实际改掉**的（都是踩出来的）

| 原规格 | 实际 | 为什么 |
|---|---|---|
| 默认 Arrow IPC | **默认 `bulk`** | 默认形态不引 arrow 就解不了 IPC；`bulk` 同档速度、零依赖。IPC 降级成 `feature "ipc"` |
| `feature "tls"` → rustls | **不做** | 见 §四：要加密就挂 TLS 终止代理。**不发布测不了的 feature**（本项目对"假承诺"零容忍） |
| `append(table, &batches)` | `append(table, &[(&str, Column)])` + `append_batches`（ipc） | 零依赖形态下没有 Arrow 批，列式输入 → `bulk` |

### 必须有的三件事——都做了（否则白做）

1. **连接复用**：keep-alive，且对端空闲回收后**自动重连重发**
   （仅限"一个字节都没写出去"，或**幂等 GET 且一个响应字节都没收到**——
   POST 绝不透明重发，`append` 非幂等）；
2. **批式**：默认列式；**不要 JSON 逐行**（体积 5–10×，且每值一次解析）；
3. **列裁剪 / 谓词下推**：**列在 SQL 里**——服务端本来就有计划级裁剪，
   客户端不重复实现，只保证不把能力丢掉（`query_stream` 走行式时读满一行是
   格式决定的，要裁剪就写进 `SELECT`）。

### 已知短板（写在最前面，别踩）

- ~~**没有参数化查询**~~ **✅ 全链路已支持**（2026-10-15）：
  内核（`docs/参数化查询设计.md`）→ 协议 `POST /api/v1/query` 的 `params`
  位置数组 → **本 crate 透出**（`Param` + `QueryOptions::params` /
  `Client::query_params`）。SQL 里写 `$1…`（可重复引用）或 `?`（按出现顺序），
  **同一句不许混用**。
  ```rust
  use qsdb_client::Param;
  let rs = c.query_params(
      "SELECT * FROM t WHERE g = $1 AND d >= ?",
      [Param::infer(10), Param::typed("DATE", "2026-01-01")],
  )?;
  ```
  **值从不进入 SQL 文本**（服务端在**绑定器**里把它们变成 AST 字面量）
  ⇒ **别把用户输入拼进 SQL**，本 crate 也不提供转义助手（"看着能跑"的转义就是注入）。
  `Param::infer` 让服务端按 JSON 形态推类型；**拿不准就 `Param::typed`**
  （它是裸值的超集）——`"2026-01-01"` 裸值会被推成 STRING，
  要跟 DATE 列比就得显式写。
  回归：`crates/qsdb-client/tests/http_wire.rs`（请求体形态 + **无参数时请求体
  逐字节不变**）+ `crates/qsdb-cli/tests/client_roundtrip.rs::参数化查询往返`
  （真 server；含"注入串只是数据"那条）。
- ~~`cancel()` 只是"被受理"~~ **已修**（2026-10-15）：根因是 `CrossJoinExec`
  一次 `next()` 展开 `n_left × n_right` 行，而 `ctx.check()` 只在入口查一次
  ⇒ 5000×5000 全在一次调用里跑完。改成**分块展开**（64K 行一块，块内每 16K 次
  再查一次）后，端到端实测 **19.7s → 26.9ms**（同一查询不取消的基线 13.2s）。
  回归 `crates/qsdb/tests/cancel_latency.rs`（判据是**比值**：取消必须比跑完快
  一个数量级——绝对秒数写死就是造一条 flaky 的尺子）。

### 会话 / 多库 / 结果护栏（十八批接入，2026-10-18）

三个 server 面（十六/十七批）在本 crate 的落点：

| 能力 | 客户端 API | 语义要点 |
|---|---|---|
| **会话** | `Client::login` / `session` / `use_database` | Basic 换进程态会话；之后撞 401 `SESSION_REVOKED` **自动重登**——**读路径**（query 全通道/rows 流/元数据 GET）单飞重登 + 原样重发一次，透明恢复；**写路径**（`execute`/`append`）只重登不重发（`append` 非幂等），原 401 返回、**重试即成功**。`Auth::Basic` 三态不变——静态场景照旧，**不 login 就没有会话**，行为与从前逐位一致 |
| **多库** | `Client::databases` + `QueryOptions::database` | `database` 优先级最高（单段表名锚定在这里）；缺省落会话默认库（`use_database`）?? `"default"`。未挂载的库名 → 404 显式拒 |
| **结果护栏** | `QueryOptions::max_rows` | **给出即接管本请求的护栏整体**（服务端行/体量两闸按此值放开或收紧；`0` = 本请求不限）；`None` = 服务器值说了算。撞 `RESULT_TOO_LARGE`（`Error::Api`，retry=no）→ 加 `LIMIT`、换 `query_stream` 流式，或本请求覆盖 |

会话回归：`client_roundtrip.rs::会话登录_踢出恢复与写路径分档`（真 server；
踢人 → 读透明恢复换新会话 / DML 与 append 错误返回重试成功 / 并发单飞）。
- ~~`cancel()` 只是"被受理"~~ **已修**（2026-10-15）：根因是 `CrossJoinExec`
  一次 `next()` 展开 `n_left × n_right` 行，而 `ctx.check()` 只在入口查一次
  ⇒ 5000×5000 全在一次调用里跑完。改成**分块展开**（64K 行一块，块内每 16K 次
  再查一次）后，端到端实测 **19.7s → 26.9ms**（同一查询不取消的基线 13.2s）。
  回归 `crates/qsdb/tests/cancel_latency.rs`（判据是**比值**：取消必须比跑完快
  一个数量级——绝对秒数写死就是造一条 flaky 的尺子）。

### 文件管理面（二十批接入，2026-10-19）

QSDB 的存储布局是**人类可导航**的（`<根>/<库名>/<表>/<分区>/seg_*.parquet`，
路径即语义）——文件浏览是本库特色，不是猎奇。四个 client 方法：

| 能力 | 客户端 API | 语义要点 |
|---|---|---|
| **目录浏览** | `Client::files_list(dir)` | `dir` = `<挂载>/<相对路径>`（与 `download_file` 同款寻址），空串 = 根。段文件（`seg_*.parquet`）**免读 parquet** 就带 `FileSegment` 摘要（referenced/rows/bytes）。`FileListing::mounts` = 调用方可见挂载，文件浏览器的起点 |
| **文件详情** | `Client::files_detail(path)` | 段带**归属**（库/表/分区）+ manifest **列统计**（min/max/NULL，不读文件）+ `read_sql`（拿去 `query` 即单文件预览，回程已由回归钉住） |
| **删除** | `Client::file_trash(path)` | 只收段文件；**被引用段 409 `SEGMENT_REFERENCED`**（删被引用段=毁表，删数据走 `DELETE WHERE`）；孤儿才进 `_trash`（静默期可 `admin trash restore`）。admin 专属 |
| **下载** | `Client::download_file(path, out)` | 二十批起从 admin 专属放宽为**读授权**（reader 本来就能 SELECT 全库）；流式、Content-Length 完整性 |

权限：读面（list/detail/download）= 对归属库有任意角色（grants 现查）；
删除恒 admin；`_trash`/`_spill`/`_filecache` 内部路径全员 403；
非 admin 列根 = **虚拟视图**（只含有 grant 的挂载名）。
契约细节：`docs/文件管理面设计.md`；回归 `crates/qsdb-cli/tests/files_manage.rs` +
`client_roundtrip.rs::files_浏览详情与回收站往返`。

## 四、传输加密：**不手搓**

- **内网明文**：默认，也是绝大多数部署的正确答案（简单、可诊断）；
- **要加密**：前面挂 **TLS 终止代理**（nginx/haproxy），或给客户端开 `--features tls` 拉 `rustls`。

> ⚠️ **不要自己写"服务端加密 / 客户端解密"**。那是"看起来加密了、其实没有"的典型，
> **比明文更危险**——它会给你虚假的安全感。手搓一套没有前向保密、没有认证、
> 侧信道没考虑、密钥轮换没设计的东西，要花两三天，然后还不如不用。

## 五、为什么 qsdb-sync **引内核是对的**（别混为一谈）

| | 形态 | 依赖内核 |
|---|---|---|
| **客户端**（业务系统 / jdbc / odbc / `qsdb-client`） | 只发请求 | ❌ 不该 |
| **生态工具**（qsdb-sync） | **搬家**：直接读 lake 格式、走 HDFS/S3、大块 bulk 导出 | ✅ **应该，而且必须** |

**判据是"它是不是另一个存储后端的搬运工"**，不是"它连不连 QSDB"。

## 六、客户端-服务器下，怎么不把内核的优势吃光

内网里**瓶颈从来不是带宽**。按杠杆排序：

1. **别把数据搬到客户端**。`SELECT *` 拉回本地再聚合是经典错。
   能在 SQL 里聚合就在服务端聚合，只搬**降维后的结果**——通常 10–1000×，其余都是零头。
2. **批式 + 列式**（§三）；
3. **连接复用 + 流水线**；
4. **列裁剪 / 谓词下推**（§三）；
5. **压缩**（IPC body 的 LZ4/ZSTD）：内网 10GbE 下**通常不划算**（CPU 换来的带宽省不掉多少），
   只在跨机房/大结果时开；
6. **大导出走 `bulk`/`rows`**，别走 SQL 结果面。

> **一句话**：省钱的不是"压得更小"，是"**少搬、少往返、列式**"。

## 七、什么情况下才该**同进程嵌入**

嵌入是**特例**，判据是「**库能不能和你同生共死**」：

- ✅ 单机分析、边缘计算、CLI/工具、测试夹具；
- ✅ 你就是那个唯一的写者，且能接受库的问题影响本进程；
- ❌ **多进程/多副本要共享同一份库** —— 我们是**单写者**
  （manifest 有 writer epoch/generation，抢写会 `STALE_WRITER`）⇒ 一个进程持有、其余走 HTTP；
- ❌ **要故障域隔离** —— 直接链 = 库崩溃会带崩业务进程
  （`catch_unwind` 的会话隔离挡得住 panic，挡不住 OOM）。

嵌入的收益：**没有序列化、没有网络、Arrow buffer 直接传**——
这也是我们那些"赢 DuckDB"的结论的**测量口径**。换成服务端形态，
这些结论要**重新验证**（见 §六）。
