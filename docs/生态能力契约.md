# 生态能力契约（对生态工具的能力承诺）

> **读者**：qsdb-jdbc / qsdb-odbc / qsdb-sync / qsdb-client，以及任何按 QSDB 写
> 工具、驱动的团队。
>
> **这份文档解决什么**：让你**不必等内核完工**就能开工。标 ✅ 的现在就能用；
> 标 ⏳ 的**协议也已经定死**（"怎么写"那一列就是最终形态），内核只是还没接上；
> 标 ✋ 的是**明确不做**（附理由）—— 别等，改写法。
>
> **内核内部的实现现状**不在这份文档里（那在 `进度与待办.md`）。这里只承诺
> **对你可见的那一面**。

---

## 一、三条纪律（**这是契约之所以是契约的部分**）

1. **状态只增不改**：`⏳ → ✅` 允许；`✅ → ⏳ / ✋` **不允许**。能力只会变多，
   不会变没。
2. **协议列不许变**：任何一格从 ⏳ 变 ✅ 时，"怎么写"那一列**一个字都不改**。
   内核内部怎么重构都行，对外的写法定死。
3. **✋ 是承诺不是待办**：标 ✋ 的是**明确不做**，理由写在下面。别按"以后会有"
   来设计你的代码。

> 例外只有一个：**发现某格写错了**（协议本身有歧义 / 实测与承诺不符）。
> 那时按 §五 的流程走 —— 先通知，不是先改。

## 二、能力表

> "协议/怎么写"列里出现 `对接契约.md` 的地方，wire 细节以那份为准（端点、请求体、
> 错误码、批量格式）。这里只说**能力与写法**。

| 能力 | 协议 / 怎么写 | 状态 |
|---|---|---|
| 查询 | `POST /api/v1/query`，体 `{"sql": "…"}` | **✅ 稳定，只增不改** |
| 写入（DDL/DML） | 同上；`/write` 只走数据通道 | **✅ 稳定** |
| 元数据 | `/tables`、`/schema`、`/partitions`、`/stats` | **✅ 稳定** |
| 批量装载 | `bulk`（列式，默认）/ `rows`（行式流式）；`/write?format=…` | ✅ |
| 取消查询 | 请求带 `X-QSDB-Query-Id`，`POST /queries/{id}/cancel` | ✅ |
| 错误码 | `GET /api/v1/error-codes`（**运行期拉，别硬编码**） | ✅ |
| `JOIN` | `INNER` / `LEFT` / `RIGHT` / `FULL` / `CROSS` / `USING` 全部支持。<br>⚠️ **大表放左边**（右表整张进内存） | ✅ |
| 聚合 `FILTER (WHERE …)` | `count(*) FILTER (WHERE …)`。谓词**不影响分组**：全不匹配的组照样出现、回 `0`/`NULL` | **✅ 2026-10-15** |
| 窗口帧 | `OVER (ORDER BY … ROWS BETWEEN a AND b)`。<br>⚠️ `RANGE`/`GROUPS` 仍 ✋；帧内一个非 NULL 都没有 ⇒ `sum/avg/min/max` 回 **NULL**（不是 0） | **✅ 2026-10-15** |
| `count(*) OVER (…)` | 同左（与 `count(x)` 的区别是"数行"vs"数非空"） | **✅ 2026-10-15** |
| 位置序号 | `GROUP BY 1` / `ORDER BY 1`（**同一套标准**：裸整数 = 投射第 n 列）。<br>也支持 `GROUP BY <表达式>`（`upper(s)` / `v % 2` / `CASE …`） | **✅ 2026-10-15** |
| CTAS | `CREATE TABLE t AS SELECT …`。<br>⚠️ 表达式列名（`count(*)`）**要么起别名、要么写显式列清单**；失败会**回滚**（不留空表） | **✅ 2026-10-15** |
| 行级 `UPDATE` / `DELETE … WHERE <非分区键>` | —— | **✋ 定位**（见 §三） |
| **提交事件订阅**（增量同步的 push 源） | `GET /api/v1/watch?since=<游标>&wait=<秒>` —— 长轮询；`reader` 角色即可。⚠️ 事件是**加速器不是真相来源**：可能丢，游标太旧会**显式报 `CURSOR_TOO_OLD`**，请保留慢轮询/对账兜底 | **✅ 2026-10-15**（`ba16ef7` 内核钩子 + `efd173b` 端点） |
| **湖导出** `COPY … TO`（parquet + hive 目录） | `COPY (SELECT …) TO '<路径>' (FORMAT PARQUET, PARTITION_BY (dt))`；分区列**只在目录名**（Spark 惯例）。路径走本仓 Store ⇒ 本地/S3/HDFS | **⏳ 设计已定** |
| **湖读取** hive 目录语义 | `read_parquet('<glob>')` —— 路径里有 `k=v` 段就**自动**把分区列组装出来（数据文件里没有它，**零文件读开销**）。类型按首个值推断；布局不一致会**显式报错** | **✅ 已可用**（F12，早于本轮；回归 `tests/external_parquet.rs::f12_hive_directory_semantics`） |
| 参数化查询 | `POST /api/v1/query`，体加可选字段：<br>`{"sql": "… WHERE g = $1", "params": [10]}`<br>· 占位符：`$1…`（可重复引用）或 `?`（按出现顺序），**同一句不许混用**<br>· 参数元素：裸 JSON 值（推类型）或 `{"type":"DATE","value":"2026-01-01"}`（显式）<br>· **个数必须正好相等**（少给/多给都 400）<br>· 驱动**不用改写 SQL**（`?` 服务端认） | **✅ 2026-10-15** |

## 三、**明确不做**的（别等，改写法）

### 行级改：没有 `UPDATE`，`DELETE` 只到分区粒度

这是**定位**，不是进度问题：本库是列存 + **段不可变**，行级改 = "读改写整个段"，
代价与语义都远超收益。

| 你想做的 | 该怎么写 |
|---|---|
| 改某几行 | `INSERT OVERWRITE`（分区级原子替换），或重写整表 |
| 删某几行 | 同上；`DELETE … WHERE <非分区键>` 不支持 |
| 删整表 / 整个分区 | `DELETE FROM t` / `TRUNCATE TABLE` ✅；`DELETE FROM t WHERE dt = '…'`（分区键）✅ |

**驱动侧请照此映射**：BI 的"编辑单元格" → `INSERT OVERWRITE`；ORM 的
`UPDATE … WHERE id = ?` → 读出来改完写回整个分区。

同档引擎也是这个语义（DuckDB 的 `UPDATE` 是删+插、ClickHouse 是异步重写分区）。

### 其他 ✋（有替代写法）

| 不做 | 替代 |
|---|---|
| `NATURAL JOIN` | 写 `ON` / `USING`（隐式按列名匹配 = 加一列就静默改语义） |
| 窗口 `FILTER` | `sum(CASE WHEN c THEN x END) OVER (…)` |
| `DISTINCT` + `FILTER` 同时写 | 拆子查询（先 `WHERE` 再 `DISTINCT`） |
| `CREATE OR REPLACE TABLE` | 先 `DROP TABLE` 再 `CREATE`；只换数据用 `INSERT OVERWRITE` |
| 非等值 `LEFT/RIGHT JOIN` | 明确的 `CROSS JOIN` + `WHERE`，或改写 |
| 一次多条语句（`;` 分隔） | 一次一条 |

## 五、变更流程

**内核侧新增能力**：改本表 §二 的状态列（⏳ → ✅）—— **协议列不动**；在
`SQL支持面.md` 补该语法的口径与实例；加**值级**回归。

**要改协议列**（§一对的例外）：**先通知生态方**，说明"原来写的会造成什么错、
新写法是什么、过渡期怎么处理"，再动。**不许先改后通知。**

**新增 ✋ 条目**：必须写明**理由**与**替代写法** —— 只说"不支持"等于把猜谜留给
调用方。

## 附：这张表怎么来的

2026-10-15 定。起因是用户拍板："**内部再乱，对外协议先钉死**；生态工具照协议
开工，我们内部慢慢对齐；进度差用一张**建设表**告诉生态'我要支持什么、协议长
什么样、做到哪了'。"

四批功能补齐（窗口帧 / `GROUP BY 1` / 聚合 `FILTER` / CTAS，见
`docs/生态功能补齐.md`）+ 参数化查询已全部落地并回填本表 ——
**表里已无 ⏳**（剩下的全是 ✋ 定位/不做项，都附了替代写法）。
