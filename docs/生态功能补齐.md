# 生态面功能补齐（**性能留最后**）

> **用户 2026-10-15 定的顺序**：先把**功能**补齐（缺的、异常的、协议说不清的），
> **性能排最后** —— 理由：性能没有卡住功能，而功能缺失会让生态工具直接没法用。
>
> **总原则**：**内部再乱，对外协议先钉死**。生态工具照协议开工，我们内部慢慢对齐；
> 进度差用一张**建设表**（§四）告诉生态"我要支持什么、协议长什么样、做到哪了"。

---

## 一、为什么是这个顺序（不是性能）

- **性能不卡功能**：慢一点的查询仍然**能跑完**，工具能出结果；
- **功能缺失卡死工具**：`ROWS BETWEEN` 拒了，Tableau 的移动平均就跑不了 —— 工具方
  没有任何绕路（等价改写是自连接，没人会那么在 BI 里写）；
- **协议的稳定性**比两者都重要：驱动/生态一旦按协议开工，我们**不能**因为内部
  重构就改协议面（`对接契约.md` §五已承诺"端点只加不改不删"）。

## 二、批次（每批自成闭环 + 过闸门 + 值级验收）

| # | 项 | 为什么排这里 | 现状 |
|---|---|---|---|
| **1** | **窗口帧 `ROWS BETWEEN …`** | 分析刚需（累计和/移动平均），且**无等价改写**；默认帧已是累计，缺的只是"自己指定帧" | ✋ 显式拒绝（曾静默用默认帧 ⇒ 错值）。**设计见 §三** |
| 2 | **`GROUP BY 1` 位置序号** | `ORDER BY 1` 是 ✅、`GROUP BY 1` 是 ✋ —— **不对称会反复踩** | ✋（2026-10-15 已把误导文案改成指名道姓）。**`ORDER BY` 有现成机制可抄** |
| 3 | **聚合 `FILTER (WHERE …)`** | 与 `DISTINCT` 同族，且此前是**静默忽略**（回全量 = 错值） | ✋ 显式拒绝 |
| 4 | **`CREATE TABLE AS SELECT`** | 常规操作 | ✋（2026-10-15 已修文案）。`CREATE` + `INSERT … SELECT` 都在，拼起来不难 |

**不做（已定案）**：
- **`UPDATE`** —— **定位声明**，不是待办：这是分析库，**没有行级 UPDATE/DELETE**；
  换数据用 `INSERT OVERWRITE`（分区级原子替换）或重写表。要写成 `对接契约.md` 的
  **一等条目**，让 BI/ORM 知道该改写而不是等我们（见 §四的建设表）。

## 三、批次 1：`ROWS BETWEEN` 的实现设计（2026-10-15 侦察完，可直接开工）

### 现状（读码所得，不是猜）

- **拒绝点**：`sql/sql/translate.rs` ~L422 `audit_window_spec`：
  `if spec.window_frame.is_some() { unsupported("window frame (ROWS/RANGE BETWEEN …) is not supported — refusing rather than silently using the default frame") }`
  ⇒ **解析层拿得到 frame**，只是被拒。
- **计划表示**：`LogicalPlan::Window { input, window_fns: Vec<WindowFn>, … }`，
  `WindowFn` 是**每函数一个变体**（`Sum(PhysExpr)` / `Avg(PhysExpr)` / `Lag(…)` / …）
  —— **没有帧字段**。
- **执行器**（`exec/window.rs ~L525-605`）：聚合窗口是**运行累加器**——
  `for i in 0..n { if partition_start[i] { acc=0; cnt=0; ext=None } ; if let Some(v) = … { acc+=v; cnt+=1; ext=min/max } ; out[i] = acc/cnt/ext }`
  ⇒ **它算的就是 `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`**（默认帧）。
  两条类型路径（整型 / 浮点）各写了一遍，`is_avg/is_min/is_max` 在内部再分派。

### 侦察补记（2026-10-15 第二轮，**改动面比预期小**）

**`WindowFn` 的构造点只有一处**：`sql/translate.rs::parse_window_fn`（~L3904）里
一个 `match name` 产出 `W::Sum(arg)/Count/Min/Max/Avg`。**改这一处就够**，
但它**签名里没有 spec**（只有 `f` + `bind` 闭包）⇒ 需要**把帧从调用方传进来**
（`parse_window_spec` 那条链上有 `spec.window_frame`）。

**执行器的接触点共 8 处**（全在 `exec/window.rs`）：
- L520 一个 or-pattern（`Sum|Avg|Min|Max`）+ L522-528 三个 `matches!`
- L609 `Count` 那块
- 其余是 `output_name` / `output_type`

⇒ **落码顺序**：① `exec/window.rs` 加 `RowFrame` 类型与 `frame()` 访问器、
变体带 `Option<RowFrame>`、8 处匹配跟着改；② 两个聚合块的**顶部**加一句
`if let Some(fr) = f.frame() { return framed_agg(...) }`（**默认帧不进这条路**
⇒ 原代码一字不改、零回归风险）；③ `parse_window_fn` 加参数 + 构造点带帧；
④ `audit_window_spec` 的整段拒绝换成"`RANGE` 仍拒 + `ROWS` 放行"。

### 三处改动

**① 计划表示**：给 `WindowFn` 的**聚合变体**带上帧（`Sum/Count/Min/Max/Avg`），
ranking/lag/lead **不带**（标准 SQL：排名函数**忽略帧**，lag/lead 也只看偏移行）。

```rust
/// 行帧（`ROWS BETWEEN a AND b`）。`None` = 默认帧（累计），语义与今天逐值相同。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct RowFrame {
    /// 起：`Unbounded` | `Preceding(n)` | `Current`
    pub start: FrameBound,
    /// 止：`Unbounded` | `Following(n)` | `Current`
    pub end: FrameBound,
}
```
⇒ 变体改成 `Sum(PhysExpr, Option<RowFrame>)` 等；**`None` 走今天的快路径**（不许变慢）。

**② 绑定期校验**（在 `audit_window_spec` 里把拒绝换成校验）：
- `ROWS` ✅ 实现；**`RANGE` 仍拒绝**（按值分帧要求 `ORDER BY` 恰好一列 + 值域语义，
  是另一件事，且更少见）；
- 非法组合显式拒：`start > end`（如 `3 PRECEDING AND 5 PRECEDING` 的倒序）、
  `UNBOUNDED FOLLOWING` 当起点、`UNBOUNDED PRECEDING` 当终点、
  `n` 为负数或超 `i64`；
- 帧 + **无 `ORDER BY`** → 按标准：整分区即帧（与默认一致）⇒ **提示但不报错**。
- **ranking/lag/lead + 帧** → 按标准**忽略**帧？⚠️ **不**：本仓纪律是"拼错就报错"，
  静默忽略正是这批要消灭的。⇒ **显式拒绝**并指路（"排名函数不吃帧，去掉 ROWS BETWEEN"）。

**③ 执行器**：`WindowFn` 有帧时走**新的滑窗路径**，`None` 时**原路径一字不改**。

```text
给定分区 [ps, pe) 与帧 a/b：
  start[i] = clamp(i - p, ps, pe)        // UNBOUNDED PRECEDING ⇒ ps
  end[i]   = clamp(i + f, ps, pe - 1)    // UNBOUNDED FOLLOWING ⇒ pe-1
  对 sum/count：前缀和（O(1)/行）；
  对 min/max：**不能**靠"减出队元素"做增量 ⇒ 分块（块内暴力、块间用单调队列）
              或先按"帧长 ≤ 阈值"暴力、超阈值再上单调队列（单调队列对 min/max 是 O(1)/行）
  对 avg：前缀和 + 计数前缀和
```
⚠️ **陷阱**：`min/max` 用单调队列时，**NULL 的占位**必须与 `cnt` 口径一致
（`count(x)` 不计 NULL、`count(*)` 计 —— 别让两者共用一份计数）。

### 验收（**每条都要能分辨对错**）

| 用例 | 期望 |
|---|---|
| `sum(x) OVER (ORDER BY i ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING)` | 逐值与手算对照（居中三行和） |
| `avg(x) OVER (… ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)` | 移动平均 |
| `sum(x) OVER (… ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)` | **必须与不带帧（默认）逐值相同** |
| `min/max` 各一条滑窗 | 单调队列与暴力逐值对照（**这是最容易写错的一条**） |
| 帧跨越**分区边界** | 不许串到隔壁分区（`partition_start` 之外的行不可见） |
| 分区内**行数 < 帧长** | 夹到分区边界（不是补 NULL、不是越界 panic） |
| 含 **NULL** 的列 | `sum/avg` 跳过 NULL，`count(x)` 不计、`count(*)` 计 |
| **`RANGE BETWEEN`** | 仍**显式拒绝**（文案说明"只实现了 ROWS"） |
| `start > end` / `UNBOUNDED FOLLOWING` 当起 | 显式拒绝 |
| **`row_number()/rank() OVER (… ROWS BETWEEN …)`** | **显式拒绝 + 指路**（不静默忽略） |
| 溢出路径（`window_spill.rs` 那条） | 帧在**逐分区**计算 ⇒ 与内存路径**逐值相同** |
| `.14` 基准 `complex_window` | **不许退化**（默认帧走原快路径） |

## 四、给生态的**建设表**（第三步产出，这里先定形态）

> 目的：让生态工具**照协议开工**，不必等内核完工。三列就够：
> **能力 | 协议（怎么写） | 状态（已支持 / 明确拒绝 / 计划支持 + 预计）**

| 能力 | 协议/写法 | 状态 |
|---|---|---|
| 查询/写入/元数据 | `POST /api/v1/query`、`/write`、`/tables`…（`对接契约.md` §三） | **✅ 稳定，只增不改** |
| 批量装载 | `bulk`(列式) / `rows`(行式) | ✅ |
| 取消查询 | `X-QSDB-Query-Id` + `/queries/{id}/cancel` | ✅ |
| 错误码 | `GET /api/v1/error-codes`（**运行期拉，别硬编码**） | ✅ |
| `JOIN`：INNER/LEFT/RIGHT/FULL/CROSS/USING | `ON`/`USING`；**大表放左边** | ✅ |
| 行级 `UPDATE` / `DELETE … WHERE <非分区键>` | —— | **✋ 定位**：分析库不做行级改；换数据用 `INSERT OVERWRITE` |
| 窗口帧 `ROWS BETWEEN` | `OVER (ORDER BY … ROWS BETWEEN a AND b)` | ⏳ 计划（本批 #1） |
| `GROUP BY 1` | `GROUP BY <列名>`（`ORDER BY 1` 已支持） | ⏳ 计划（#2） |
| 聚合 `FILTER (WHERE …)` | `count(*) FILTER (WHERE …)` | ⏳ 计划（#3） |
| CTAS | `CREATE TABLE` + `INSERT INTO … SELECT …` | ⏳ 计划（#4，**已有替代写法**） |
| 参数化查询 | —— | ⏳ 计划（协议面加 `params`；**客户端别自己拼 SQL**） |

**纪律**：表里的"状态"**只增不改**；任何一格从 ⏳ 变 ✅ 时，**协议列不许变**。
