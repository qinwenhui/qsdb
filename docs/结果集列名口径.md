# 结果集列名口径（F30）

> **读者**：内核绑定器 / 驱动 / BI 对接方。
> **起因**：qsdb-sync 的 F30（2026-10-17）——*未起别名的列名不是合法标识符*。
> **定案**：用户 2026-10-17 拍板 —— **只剥限定符**（不编造表达式名）。
>
> **这是协议面变更**：结果集 schema 就是 JDBC/ODBC 元数据面看到的列名。
> 按 `生态能力契约.md` §五，**先出设计 → 实现 → 通知生态方**，不许先改后通知。

---

## 一、现象（qsdb-sync 报的 + 本轮实测）

**他们那张表我逐条复现，4/4 全对**：

| 写法 | 我们 | PostgreSQL |
|---|---|---|
| `SELECT t.v FROM t` | `t.v` | `v` |
| `SELECT t.id, u.name FROM t JOIN u ON …` | `t.id`, `u.name` | `id`, `name` |
| `SELECT count(*) FROM t` | `count(*)` | `count` |
| `SELECT t.v + 1 FROM t` | `t.v + 1` | `?column?` |
| `SELECT t.v AS v` | `v` ✅ | `v` |

**外加一条他们没提的**（`SELECT *` 的左右不对称）：

| 写法 | 我们 | PostgreSQL |
|---|---|---|
| `SELECT * FROM t JOIN u ON t.id = u.id` | `id, v, u.id, u.name` | `id, v, id, name` |

（左裸右限定 —— 那是**绑定**侧的刻意设计「裸名恒解析到左表」，但它**泄漏进了输出名**。）

### ★★ 实测多挖出的两条（**都比"列名不好看"重**）

**① 限定名泄漏进派生表 ⇒ 正常 SQL 直接失败，而且报了个不着边际的错**

```sql
SELECT v FROM (SELECT t.v FROM t) x
```

```
not found: column 'v' (a JOIN right-side column with this name exists —
qualify it as `t.v`: unqualified names resolve to the left input only)
```

**这句里根本没有 JOIN。** 用户写的是最标准的派生表投影。
根因在 `bind_expr` 的「找不到就给 JOIN 提示」那段：它按**尾名**猜"这大概是个 JOIN
右表列"，而这里的 `t.v` 只是**投影输出名**恰好像个限定名。**F29 同族**：
把一种情况说成另一种，用户会往完全错误的方向排查。

**② 重名引用是静默取第一个（PG 报 ambiguous）**

```
SELECT v FROM (SELECT 1 AS v, 2 AS v) x   →  1   （不报错）
SELECT v FROM (SELECT 2 AS v, 1 AS v) x   →  2   （不报错）
```

`SchemaCtx::index_of` 用 `position()` —— **命中多个取第一个，一个字都不说**。
这是**既有的静默错值**，今天只是很少有人故意起两个同名（见 §三：改完就不是了）。

**③ 同一个内核里已经有两套口径**（这条是"该改"的最硬证据）

| 路径 | `SELECT t.id, u.name FROM t JOIN u …` 的列名 |
|---|---|
| 结果集 / 驱动元数据 | `t.id`, `u.name` |
| **`CREATE TABLE … AS SELECT …`** | **`id`, `name`**（`strip_table_qualifier` 剥了） |

而且 CTAS 走**重名报错**那条路（`CTAS 推导出的列名有重复`）—— **它本来就是对的**。
⇒ 本仓不是"要不要跟 PG"，而是**结果集这条路漏了 CTAS 早就做对的事**。

---

## 二、定案：只剥限定符

### ★ 分界线：**剥掉限定符 ≠ 编造名字**

这两件事长得很像（都是"改输出名"），但性质相反：

| | 例 | 用户的视角 | 处置 |
|---|---|---|---|
| **剥限定符** | `t.v` → `v` | `v` **就是**他写的那个列名；去掉的是**消歧用的表限定**（不是名字的一部分） | ✅ **做** |
| **编造名字** | `count(*)` → `count` | `count` 是他**从没写过**的东西 | ✋ **不做** |

第二条与本仓 CTAS 里已经写死的理由**是同一条**（`SQL支持面.md` §五）：
*"本仓不替用户改名 —— PG 会改成 `count`，那是另一种静默（表里出现你没写过的列名）"*。
而"名字不够好看"这条**有零成本出路**：写 `AS`（qsdb-sync 已经这么绕开了）。

> 注：PG 自己在这一格上也不统一 —— `count(*)` 在 MySQL 里就叫 `count(*)`。
> 我们选的是"**用户写什么就是什么**"。

### 具体规则

| AST 形态 | 输出名 |
|---|---|
| `Expr::Identifier(id)`（`SELECT v`） | `id.value`（本来就没有限定） |
| `Expr::CompoundIdentifier([t, v])`（`SELECT t.v`） | **`v`**（取最后一段） |
| 其它表达式（`count(*)` / `t.v + 1` / `sum(v)`） | **`expr_display(e)` 原样** |
| 任何形态 + `AS x` | `x`（不变） |
| `SELECT *`（含 join） | `ctx.cols` 里的名字**逐个剥限定** |

---

## 三、★★ 必须**同批**做的那条：重名引用报错

**只剥限定符、不管歧义，会把一个能跑的查询变成静默错值：**

```
今天：  SELECT a.v, b.v FROM a JOIN b   → 列名 a.v, b.v  各自唯一 ⇒ 外面引用得动（虽难看）
只剥：  SELECT a.v, b.v FROM a JOIN b   → 列名 v, v      ⇒ 外面 SELECT v FROM (…) x 静默取第一个
```

而「JOIN 两侧同名列」是**极常见**的形状（`a.id, b.id` 几乎每个 join 都有）。
⇒ **不许只做前半条。**

**做法**：`SchemaCtx` 加一个"用户引用"用的解析入口（`index_of` 保留给内部探测）：

- 命中 **0** 个 → `column not found`（**保留现有那条 JOIN 提示**，但要收紧：只在
  ctx 里真有**带限定的**同尾名列时才提示，别对着派生表乱说 JOIN）
- 命中 **1** 个 → `Ok(idx)`
- 命中 **>1** 个 → **`column reference 'v' is ambiguous`**（PG 的措辞），
  **不是**"找不到"

用在：`bind_expr` 的 `Identifier` / `CompoundIdentifier`、`ORDER BY <输出名>`
（`out_ctx.index_of`）。`is_some()` 那种**探测型**调用（相关子查询判内外侧）保持原样。

> ⚠️ **为什么歧义只会在派生表/CTE 出现**：基表/join 的 `ctx.cols` 天然无重名
> （左裸右限定，且列名不许带 `.`）⇒ 这条检查不会误伤正常查询。

## 四、实现面

| # | 位置 | 改动 |
|---|---|---|
| 1 | `translate.rs` `SelectItem::UnnamedExpr` 分支 | 旧的 `name: expr_display(e)` ⇒ **裸列引用取末段**，其余原样 |
| 2 | `translate.rs` `SelectItem::Wildcard` 分支 | `name: name.clone()` ⇒ **剥限定**（`sql` 仍用全名，绑不定不动） |
| 3 | `strip_table_qualifier`（现在在 `sql/mod.rs`，私有） | 提到两处都能用（`pub(crate)` / 挪进 `translate.rs`） |
| 4 | `SchemaCtx` | 加 `resolve(name) -> Result<usize>`（重名报错）；`bind_expr` 两个引用点改用它 |
| 5 | `bind_expr` 的 JOIN 提示 | 收紧判据，别再对着派生表说 "a JOIN right-side column" |
| 6 | CTAS 里的 `strip_table_qualifier` | **保留**（对已剥的名是 no-op，防御性；显式列清单那条路仍要） |

### ★ 实现时才暴露的两条（设计稿原版没有，都是**跑红了才知道**）

**A. `SELECT *` 必须改成"按下标绑"，不能走名字解析**

剥完限定符之后，派生表里会出现重名（`SELECT a.id, b.id …` 的输出就是两个 `id`）。
而 `SELECT *` 恰恰要**原样透传**它们 —— `SELECT * FROM (SELECT a.id, b.id …) x`
在 PG 里就是出两个 `id`。按名字绑会在那里报 `ambiguous`，
但**那根本不是"用户在引用一个名字"**，是通配展开 ⇒ 按下标才是它本来的语义。

做法：`ProjItem` 加 `wild_idx: Option<usize>`，通配项在非聚合分支直接产出
`PhysExpr::Column{idx}`，绕过 `bind_expr`。
（聚合分支**不**走这条捷径 —— `SELECT *, count(*)` 今天本来就报错，保持原样，
不许因为"顺手"把 `win_agg_ctx` 的下标空间搞混。）

**B. `ORDER BY` 要按"投影**表达式原文**"匹配，不是按名字末段**

投影名剥了限定之后，`SELECT d.label … ORDER BY d.label` 按名再也比不中
（投影名叫 `label`，ORDER BY 写的是 `d.label`）—— 既有用例 `join_right_external`
当场红。

⚠️ 修法**不能**是"按末段再匹配一次名"：那样 `ORDER BY b.id` 会匹配到碰巧叫 `id`
的**另一个**投影列（`a.id`）—— 值全对、**顺序错**，最难发现的一类。
正确做法是拿 `items[i].sql` 的**原文**（`expr_display`）去比。
（⚠️ 用 AST 的 `expr_display`，**不能**用 `PhysExpr::display()` —— 后者带括号
`(t.v + 1)`，两个渲染器永远比不中，本仓栽过一次。）

**C. 一处副作用（与 PG 一致，但要知道）**

派生表里的**限定名不再可引用**：`SELECT u.name FROM (SELECT * FROM t JOIN u …) x`
改之前能跑（`u.name` 恰好是那层的 ctx 名），改之后不行。
PG 同样不行（那一层的列叫 `id, v, id, name`，没有 `u` 这个表）⇒ 视为**对齐**，
不是回归。

---

**风险面**（改之前先想清楚这四处）：

- **`ctx.cols` 同时供"绑定"和"`SELECT *` 展开"两条路用**。只改**输出名**、
  不改 `cols` 本身 —— 绑定语义一个字不动。
- **`SELECT * FROM t JOIN u` 会真的产出两个 `id`**（PG 也这样）。结果集允许重名
  （表不允许），所以这对；但**下游按名取值的工具会撞**——那正是 §三 要报错的地方。
- **内部按名查输出列的路径**（`plan_output_columns` 的消费者：CTAS / UNION / CTE /
  派生表 / `ORDER BY`）全都要过一遍，确认重名会被**报出来**而不是被随便取一个。
- **`__sort_N` 隐藏列**那条路（ORDER BY 追加）不受影响，但要回归。

## 五、验收（`tests/result_column_names.rs`）

1. **列名**：`t.v`→`v`；`SELECT * FROM t JOIN u` → `id, v, id, name`；
   `count(*)` / `t.v + 1` / `sum(v)` **原样**；`AS x` 原样。
2. **派生表闭环**（第 ① 条的回归）：`SELECT v FROM (SELECT t.v FROM t) x` **能跑且值对**；
   `SELECT x.v FROM (…) x` 也能。
3. **重名报错**（第 ② 条）：`SELECT v FROM (SELECT 1 AS v, 2 AS v) x` → **报错且文案含
   `ambiguous`**（不是 `not found`，也不是静默取第一个）。
4. **JOIN 同名列**：`SELECT * FROM (SELECT a.id, b.id FROM a JOIN b ON …) x` →
   两列都在；`SELECT id FROM (…) x` → **报错**。
5. **CTAS 不回归**：`CREATE TABLE c AS SELECT t.id, u.name FROM t JOIN u …` → 列名
   `id`/`name`；`CREATE TABLE c AS SELECT count(*) FROM t` → **仍拒**（文案不变）。
6. **绑定不回归**：`SELECT t.v, u.name FROM t JOIN u ON t.id = u.id ORDER BY t.v`
   （限定名照样能写，只是**输出名**变了）；`GROUP BY` / `HAVING` / 相关子查询全跑一遍。
7. **HTTP 面**：`/query` 返回的 schema 列名 = 同一批名字（`http_contract.rs` 补一条）。

| 谁 | 影响 |
|---|---|
| **qsdb-sync** | ✅ **正是他们 F30 的解法**：sink 按结果集 schema 建表不再需要"每列显式起别名"（`e2e_wide_table.rs` 里那条绕法可以留着，但不再是必须） |
| qsdb-jdbc / qsdb-odbc | 元数据列名变短（`t.v`→`v`）；`findColumn("v")` 从**找不到**变**找得到**。**只变好** |

## 七、明确不做

| 不做 | 理由 |
|---|---|
| `count(*)` → `count`、`sum(v)` → `sum` | 编造用户没写过的名字（§二）；`AS` 是零成本出路 |
| 表达式列名 → `?column?` | PG 那个名字同样不是标识符，换了没收益；保留原文更有信息量 |
| 直接**拒绝**重名结果集（`SELECT a.v, b.v`） | 比 PG 严，且会让今天能跑的 `SELECT a.id, b.id` 变红。**结果集允许重名，只有"按裸名引用"才有歧义** |
| 顺带把 `NATURAL JOIN` / 限定通配 `t.*` 补上 | 与本题无关，别混进来 |
