# QSDB 对接契约（外部工具/团队接口承诺）

> 版本：v1（2026-10-11）——qsdb-sync 等生态工具的对接基准
> 读者：同步工具团队、嵌入方、运维工具作者
> 原则：**本文列出的 = 承诺稳定的契约面**；未列出的 pub 项 = 内部实现，
> 可能随版本变化（不通知不迁移）。变更契约项需 major 版本 + 迁移说明。

---

## 一、表格式（物理契约，最强承诺）

权威文件：`docs/format-spec.md`（**已冻结**）。要点承诺：

1. 目录布局 / manifest 结构 / segment 命名 / 编码**不变更**；
   演进只走「追加式」（如 `writer_epoch` 字段带 `serde(default)`）
2. **segment 不可变**（UUID v7 名，单次写入）——拷贝即复制，无变更语义
3. **分区单一 manifest = 唯一真值**；`generation` 单调递增——
   这是同步工具的增量判据与幂等依据
4. 同一格式跨全部后端（本地 / S3 / HDFS 同 key 布局）——工具写一次通吃
5. 多写者协议：外部进程与 QSDB server 可同时写同一数据目录
   （分区 flock / 远端条件写协调），外部写入对 server **即时可见**
   （无通知通道：真值在盘上，读侧自带失效）

## 二、嵌入 API 契约（qsdb crate）

| API | 语义要点 |
|---|---|
| `Qsdb::open(root, opts)` / `open_with_store` | 打开/初始化；句柄 Send+Sync 可克隆共享 |
| `Qsdb::append(table, &[RecordBatch])` | Arrow 批直入，自动分区路由；宽松写（缺尾列补 NULL） |
| `Qsdb::overwrite_partition(...)` | 分区原子替换（幂等回写原语）；空输入 = 清空分区 |
| `Qsdb::scan(ScanRequest)` / `scan_with_context` | 流式迭代器 + 三级裁剪 + 谓词下推 |
| `Qsdb::sql(&str)` / `sql_collect` | `SqlResult::Query { schema, batches }`——**LIMIT 0 返回空批 + 完整 schema**（schema 协商契约） |
| `Qsdb::partition_stats(table)` | `Vec<PartitionStat { name, generation, rows, segments }>`——同步轮询契约（索引快路径） |
| `Qsdb::read_only()` | 只读模式标志（见 §四） |
| `db.writer(WriteBufferOptions)` | 攒批写（高频小批 → 大段） |
| `Qsdb::flush_staged()` / `staged_pending()` | staging 写的补传/诊断（远端模式） |
| `Qsdb::gc()` / `compact_table(_with)` | 运维动作 |
| `PartitionManifest` / `SegmentEntry` / `list_partitions` | 表格式读写面（与 §一 同构冻结） |
| `LogicalType::try_from_arrow` | 类型映射辅助（Arrow → QSDB 类型） |

类型系统：进出皆 Arrow `RecordBatch`——同步工具的中间表示零转换。
约束语义：NOT NULL / CHECK 在写入端强制（工具侧无需重复校验）。

## 三、HTTP / Flight 契约（qsdb server）

| 端点 | 契约 |
|---|---|
| `POST /api/v1/write?table=T&mode=append\|overwrite` | body = Arrow IPC 流；overwrite = 分区级替换 |
| `POST /api/v1/query` | SQL 文本 → json/ipc；LIMIT 0 契约同上 |
| `GET /api/v1/tables/{t}/partitions` | `{ partitions: [名], count, detail: [{name, generation, rows, segments}] }`——**detail.generation 为同步增量判据** |
| `GET /api/v1/tables` / `tables/{t}/schema` | 发现与 schema |
| `GET /api/v1/stats` / `metrics` | 容量与 prometheus 指标 |
| Flight（feature） | do_get ticket=SQL；do_put cmd=`table:<名>` |

鉴权：Bearer token（`--token`）。错误：4xx/5xx + 文本消息。

## 四、行为契约

1. **只读模式**（`QsdbOptions.read_only`）：写/DDL/compact/gc 全拒
   （错误含 "read-only"）；server /write → 503。standby/只读副本标准姿势。
2. **Durability 两档**：默认 ProcessCrash（kill -9 安全）；PowerLoss
   （fsync 掉电安全，吞吐 -25%）。工具侧无需关心，仅部署参数。
3. **可见性**：append/overwrite 返回即对后续查询可见（manifest 已提交）；
   staging 模式例外（flush 前不可见，文档化语义）。
4. **写幂等性边界**：append 非幂等（重试可能重复入段）——工具要 exactly-once
   请用 overwrite_partition 或自身位点管理（参考 qsdb-sync 设计 §十）。
5. **Schema 演进**：ALTER ADD COLUMN 后旧段可读（缺列补 NULL）；
   前缀兼容规则见 format-spec §7.1。删列/改型不支持——工具侧 check 报告。

## 五、版本与兼容承诺

- 表格式：冻结（见 §一）；manifest 追加字段必带 `serde(default)` 向后兼容
- 嵌入 API：semver——minor 只加不改，major 可改（提前一版 deprecate 注记）
- HTTP/Flight 契约：端点只加不改不删；字段只加（消费方须容忍新增字段）
- 升级路径：QSDB 版本升级不触碰数据目录格式（工具无需数据迁移）

## 六、给 qsdb-sync 团队的最小对接清单

1. 读：`partition_stats`（或 HTTP detail）判增量 → 拷新 segment → 应用 manifest
2. 写：嵌入 `append` / `overwrite_partition`（或 HTTP write）+ `_sync.checkpoints` 普通表存位点
3. 协商：`sql("SELECT … LIMIT 0")` 取 schema 比对（`qsdb-sync check`）
4. 详细协议：`docs/主备与qsdb-sync设计.md`（复制协议 §3 / 语义 §十）
