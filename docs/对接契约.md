# QSDB 对接契约（外部工具/团队接口承诺）

> 版本：v1（2026-10-11）——qsdb-sync 等生态工具的对接基准
> 读者：同步工具团队、嵌入方、运维工具作者
> 原则：**本文列出的 = 承诺稳定的契约面**；未列出的 pub 项 = 内部实现，
> 可能随版本变化（不通知不迁移）。变更契约项需 major 版本 + 迁移说明。

---

## 一、表格式（物理契约，最强承诺）

权威文件：`docs/format-spec.md`（**已冻结**）。要点承诺：

1. 目录布局 / manifest **字段结构** / segment 命名 / 编码**不变更**；
   演进只走「**尾部追加**」——⚠️ 但**追加字段必须同时 bump `manifest.version`**，
   而且**读者要保留对旧版本的读路径**。原因是 postcard **不是自描述格式**：
   `#[serde(default)]` **给不了任何兼容性**（尾部加字段 ⇒ 旧文件"读穿了"）。
   *（本节 2026-10-14 之前的措辞是"追加式 + `serde(default)` 即向后兼容"——**那是错的**，
   `epoch` 落盘后旧数据被读成 `corrupt manifest`；详见 `format-spec.md` §7。）*
   **对工具的含义**：内核保证**能读 v1 和 v2**（见 `format-spec.md` §7）；
   **不要自己解 postcard 字节**——用内核 API（`PartitionManifest::read` / `partition_stats`），
   或至少同时接受 v1/v2 两个版本号。
2. **segment 不可变**（UUID v7 名，单次写入）——拷贝即复制，无变更语义
3. **分区单一 manifest = 唯一真值**；`generation` 单调递增——
   这是同步工具的增量判据与幂等依据
4. **写者身份代 `manifest.epoch`（F25/F26）**——同步工具的判据是
   **`(epoch, generation)` 复合序**，不是单独的 `generation`：
   - `generation` 是**分区提交计数器**（每次提交 +1），回答"改过几次"；
   - `epoch` 是**写者身份**（`QsdbOptions::writer_epoch` / CLI `--writer-epoch`，
     默认 0），回答"这块数据属于哪一代写者"——**只有运维动作会抬高它**
     （接管时配一个比原主库大的值），进程永不自增。
   - **承诺**：凡是产生一次分区提交的路径都**既校验又盖章**（append / overwrite /
     `INSERT OVERWRITE` / compaction / 清空分区 / `TRUNCATE`，本地与远端同口径，
     含**无分区表**与 staging 写）。故盘上 `epoch` 恒等于最后提交者的配置值。
   - 为什么不能只看 `generation`：它是计数器不是内容指纹，脑裂后两边独立演进
     **恰好追平到同一个值**时会误判 up_to_date 而**静默分歧**；epoch 不同即拒绝协商。
   - 内核自己也不许回退写：盘上 `epoch` > 本进程配置 → 写被拒，
     `STALE_WRITER`（409 / `retry=no` / SQLState `40001`），**被拒的写不动数据**。
5. 同一格式跨全部后端（本地 / S3 / HDFS 同 key 布局）——工具写一次通吃
6. 多写者协议：外部进程与 QSDB server 可同时写同一数据目录
   （分区 flock / 远端条件写协调），外部写入对 server **即时可见**
   （无通知通道：真值在盘上，读侧自带失效）

## 二、嵌入 API 契约（qsdb crate）

| API | 语义要点 |
|---|---|
| `Qsdb::open(root, opts)` / `open_with_store` | 打开/初始化；句柄 Send+Sync 可克隆共享 |
| `Qsdb::append(table, &[RecordBatch])` | Arrow 批直入，自动分区路由；宽松写（缺尾列补 NULL） |
| `Qsdb::overwrite_partition(...)` | 分区原子替换（幂等回写原语）；空输入 = 清空分区 |
| `Qsdb::overwrite_partition_cas(..., expected_generation)` | 同上 + **乐观并发（F24）**：分区当前 `generation` 不符 → `WriteConflict`（409/`WRITE_CONFLICT`/`40001`）。不传 = 无条件覆盖（向后兼容） |
| `Qsdb::scan(ScanRequest)` / `scan_with_context` | 流式迭代器 + 三级裁剪 + 谓词下推 |
| `Qsdb::sql(&str)` / `sql_collect` | `SqlResult::Query { schema, batches }`——**LIMIT 0 返回空批 + 完整 schema**（schema 协商契约） |
| `Qsdb::partition_stats(table)` | `Vec<PartitionStat { name, generation, rows, segments }>`——同步轮询契约（索引快路径） |
| `Qsdb::read_only()` | 只读模式标志（见 §四） |
| `db.writer(WriteBufferOptions)` | 攒批写（高频小批 → 大段） |
| `Qsdb::gc()` / `compact_table(_with)` | 运维动作（同样是**写者**：过期 `epoch` → `STALE_WRITER`） |
| `QsdbOptions::writer_epoch` | 写者身份代（默认 0 = 不启用）；见 §一.4。CLI `--writer-epoch` |
| `Qsdb::flush_staged()` / `staged_pending()` | staging 写的补传/诊断（远端模式）；**提交在 flush 时刻，身份代校验也在那时**——故旧代写者的 staged 数据 flush 时报 `STALE_WRITER` 且不落盘 |
| `PartitionManifest` / `SegmentEntry` / `list_partitions` | 表格式读写面（与 §一 同构冻结） |
| `LogicalType::try_from_arrow` | 类型映射辅助（Arrow → QSDB 类型） |

类型系统：进出皆 Arrow `RecordBatch`——同步工具的中间表示零转换。
约束语义：NOT NULL / CHECK 在写入端强制（工具侧无需重复校验）。

### 二之二、`#[non_exhaustive]` 规则（嵌入方编译稳定性，qsdb-sync F27）

**为什么**：J12 给 `SqlResult::Ok` 加了两个字段，HTTP 面向后兼容，但 **Rust API 面
把首个嵌入方（qsdb-sync）的编译打断了**（穷尽匹配 → E0027）。这是一次**已实测**的
代价，不是推测。

**规则**（2026-10-13 定）：

| 类型类别 | 处理 | 理由 |
|---|---|---|
| **内核产出、嵌入方只消费**：`SqlResult`、`QsdbError`、`WriteResult`、`CompactResult`、`PartitionStat` | **标 `#[non_exhaustive]`** | 加变体/加字段不该打断嵌入方；嵌入方本就该按 `..` 取值 |
| **嵌入方要构造或按字段取值的输入/格式类型**：`Literal`、`LogicalType`、`ScanRequest`、`QsdbOptions`、`Predicate`、`SegmentEntry`、`PartitionManifest` … | **不标** | 标的副作用是**禁止外部构造**（E0639）——格式面工具必须能造 |

**实测的语义细节（重要，别"优化"掉）**：
1. **枚举级标注防不住"给变体加字段"**：它只要求外部加通配臂（E0004）；外部若把
   变体字段列全了，加字段照样报 **E0027**。**必须同时标在变体上**，变体级才会强制
   外部写 `..`（E0638）。
2. 变体级标注会**禁止外部用结构体字面量构造该变体**（E0639）——故规则第二类不能标。
3. 已用两个小 crate 端到端验证：变体级标注后，**给变体加字段、外部一字未改，照样
   编译通过**。

**嵌入方需要做的一次性适配**（只此一次，之后内核加变体/加字段都不再打断你们）：

```rust
// 枚举级 → 必须留通配臂（放最后，放前面会让上面的臂不可达）
match db.sql(sql)? {
    SqlResult::Query { schema, batches, .. } => { /* 变体级 → 必须写 .. */ }
    SqlResult::Ok { message, .. } => { ... }
    _ => { /* 内核将来加的新变体 */ }
}
// 结构体同理：PartitionStat { name, generation, .. }；别用字面量构造产出类型
```

### 二之一、查询结果的形状承诺（2026-10-13 收紧）

| 情形 | 承诺 | 备注 |
|---|---|---|
| **无 `GROUP BY` 的聚合**（含空输入） | **恰好一个批、恰好一行**：`count`→`0`，`sum`/`avg`/`min`/`max`→`NULL` | 此前空输入回**零个批**（网线上是空数组）——`SELECT count(a) FROM t WHERE <不匹配>` 会给客户端"没有结果"而不是 `0`。已修 |
| **零行结果** | **一个空批 + 完整 schema**（`LIMIT 0` 是标准姿势） | `SqlResult::Query.schema` 本就带列名；现在**批也带**，逐批消费的调用方不必再特判。可观测变化：`format=ipc` 的批数从 0 变 1（空批），**行数仍是 0** |
| **有 `GROUP BY` 且零组** | 零行（**不**补行） | 与上一条正交，别混 |

**聚合参数上的 `DISTINCT` 已原生支持**（2026-10-14）：`count/sum/avg/min/max(DISTINCT x)`
直接写即可，语义与 PG/DuckDB 一致（**跳过 NULL**）。此前它**被静默丢弃**
（当成 `count(x)` 执行、回**错的数字**），后来一度显式报错，现已补齐。

> ⚠️ **给已经采纳过"等价改写"的建议的对接方**：`docs/生态工具升级通知.md` 早先推荐的
> 那条 workaround（`SELECT g, count(*) FROM (SELECT DISTINCT g, a FROM t) GROUP BY g`）
> **在 2026-10-14 之前会回错数字**——列裁剪的一个索引空间缺陷会把外层引用的列指到隔壁
> （已修，回归 `crates/qsdb/tests/projection_space.rs`）。若你用那条改写算出的数落过盘/
> 进过报表，**建议按原生写法重算一次**。
> ⚠️ **F28（2026-10-15，qsdb-sync 指出）**：那条子查询改写**必须写 `count(x)`，
> 不能写 `count(*)`** —— `SELECT DISTINCT x` 会保留一行 NULL，`count(*)` 把它算进去，
> 于是"该组含 NULL"时会**多 1**。我们早期通知里推的是 `count(*)` 那版，**那是错的**；
> 也别拿它当交叉校验（对照只会把对的改错）。详见
> [`docs/生态工具升级通知.md`](生态工具升级通知.md) 的对照表。

**仍然显式拒绝**（`UNSUPPORTED`，别重试，改 SQL 才有用）：

```sql
SELECT count(DISTINCT x), count(x)   FROM t;  -- 混用：一次去重会改掉 count(x) 的输入
SELECT count(DISTINCT x), count(DISTINCT s) FROM t;  -- 参数不同：没法共享一次去重
```

带分组的写法没有限制：`SELECT g, count(DISTINCT x) FROM t GROUP BY g` 原生可用
（注意某组只有 NULL 时该组**仍然回一行、值为 0**）。

**分区表的 DDL 约束收紧**：分区表**至少要有一个非分区列**。分区列的值存在目录名里、
不进数据文件，所以"所有列都是分区列"的表数据文件是零列的——那种文件**别的引擎
读不了**（DuckDB：`Need at least one non-root column in the file`），我们自己也读不回
行数（除 `count(*)` 外每个查询都静默回空）。主流（DuckDB/Hive/Spark/Delta…）同样拒绝。

## 三、HTTP / Flight 契约（qsdb server）

| 端点 | 契约 |
|---|---|
| `POST /api/v1/write?table=T&mode=append\|overwrite` | body = Arrow IPC 流；overwrite = 分区级替换。**`&format=ipc\|bulk\|rows\|csv`** 选 body 编码（列序一律 = **表列序**）：`bulk` = [无依赖列式](bulk-format.md)（列式生产者），**`rows` = [无依赖行式](rows-format.md)（驱动按行取值、可流式分块，schema 由 `table=` 给）**，`csv` = 文本。<br>⚠️ **`format` 缺省是 `ipc`，且服务端不按 `Content-Type` 分派**（只看这个查询参数）——递 `bulk` 字节却不带 `&format=bulk` 会回 `INVALID_IPC`（一个**看着像客户端 bug、其实是漏参数**的错）。`qsdb-client` 是踩到这一条之后才把 `format` 定成必给的（见 `crates/qsdb-cli/tests/client_roundtrip.rs`） |
| ↑ 可选 `&expected_generation=N`（别名 `expectedGeneration`） | **F24 CAS**：`mode=overwrite` 时要求该分区当前 `generation == N`，否则 409 `WRITE_CONFLICT`。**只支持单分区**（一次请求命中多个分区 → 400 `INVALID_ARGUMENT`，因为"期望 generation"没有唯一所指）；用于 append → 400。不传 = 现状行为 |
| `POST /api/v1/query` | SQL 文本 → `"format": "json"\|"ipc"\|"bulk"\|"rows"\|"csv"`（默认 json）；响应含 `queryId`（见下）；**可经请求头 `X-QSDB-Query-Id` 在执行前指定 id（J11）** |
| `GET /api/v1/tables` | `{"tables": [名]}`；**`?withSchema=1`** 返回 `[{name, columns:[{name,type,nullable,partition}]}]`（一次拿全列集，消除 getColumns 的 N+1） |
| `GET /api/v1/tables/{t}/schema` | `{table, columns: [...]}` |
| `GET /api/v1/tables/{t}/partitions` | `{ partitions: [名], count, detail: [{name, generation, rows, segments}] }`——**detail.generation 为同步增量判据** |
| `GET /api/v1/users/export` | **用户面导出**（qsdb-sync 用户面同步的 HTTP 源）。体与 `qsdb admin user-export` **同源**：`{"users":[{name,role,salt,hash}]}`，**含口令哈希、不含明文**，可直接喂 `UserStore::import_json`（replica 的 `--users` = export src → import dst）；**admin 专属**（403 `FORBIDDEN`）。回归含**往返**验证（`http_contract::users_export_over_http_roundtrips_into_import`） |
| `GET /api/v1/stats` / `metrics` | 容量与 prometheus 指标 |
| `GET /api/v1/error-codes` | **错误码目录**（静态，免鉴权）：`{version, codes:[{code, http, retry, category, sqlState}]}`。驱动冷启动即可自配置 code→SQLState/重试映射，不必硬编码码表；内核加码时驱动自动跟上。目录语义以 [`docs/error-codes.md`](error-codes.md) 为准 |
| `GET /health` | 存活探针，**不鉴权**，返回 `{"status":..., "version":...}`（公网部署注意版本暴露；探针需开放端点，`--health-public=false` 可收紧） |
| `POST /api/v1/auth/login` | Basic 认证 → 签发进程态 Bearer token（连接池用户友好：token 轮换无需改配置） |
| Flight（feature） | do_get ticket=SQL；do_put cmd=`table:<名>` |

### 3.1 鉴权（J9）

- **Bearer token**：静态 `--token`（运维全局凭证）或 `/auth/login` 签发的进程态 token
- **Basic**：`Authorization: Basic <b64(user:pass)>` 直接按用户名密码解析角色
- 优先级：Bearer 用户 token > Basic > `--token` > 开放（未配置时）

### 3.2 错误响应（J3/J5）

错误体**恒为** `{"error": <人读文案>, "code": <机器码>}`：

> **包含框架层抽取失败（2026-10-12 起）**：请求体非法 JSON、body 字段类型/缺失、
> query string 缺参——一律**同形错误体** + `INVALID_ARGUMENT`
> （`422`/`415` 一并归一为 `400`，否则一个码会对应三种状态码）。
> 此前这几类回的是纯文本、无 `code`，驱动只能按文案猜；已修，并有回归测试守着
> （`crates/qsdb-cli/tests/http_contract.rs`）。

> **没有目录外的码（2026-10-12 起）**：状态派生兜底（`status_code_of`）已删除，
> `code` 只可能取码表里的值。目录可经 `GET /api/v1/error-codes` 运行期拉取。

- `code` 是**契约级稳定**标识，据此精确映射 SQLState；`error` 文案可能随版本变化，
  消费方**不应**依赖其内容（此前只能靠 message 前缀 `"query timeout: "` 识别超时）
- **完整码表（含 HTTP 状态码、可重试性、SQLState 建议、演进政策）见
  [`docs/error-codes.md`](error-codes.md)——权威且唯一**。本文不再复制该表，
  避免两处漂移（该文 §8.2 列出尚未落地的差异，实施后完全对齐）
- 三条最易混的语义（详见该文 §四）：
  - **503 有三种，别按状态码一刀切**：`TOO_MANY_QUERIES`（并发条数满 → **可退避重试**）、
    `MEMORY_PRESSURE`（全库内存预算被占 → **可退避重试**）、`READ_ONLY`（只读库 →
    **永不重试**）
  - **"内存不够"有两种**：`QUERY_MEMORY_LIMIT`（400，你的查询超了自己的配额）与
    `MEMORY_PRESSURE`（503 可重试，全库此刻吃紧）——**客户端动作相反**，别混
  - **查询端点**的表/列不存在 → **400**（`TABLE_NOT_FOUND` / `COLUMN_NOT_FOUND`，
    SQL 语义面，避免网关把 SQL 错判成路由错）；**资源端点**的对象不存在 → **404**
    （`NOT_FOUND`，保住 HTTP 语义）
  - **401 与 403**：401 = 不知你是谁（重新认证）；403 = 知道你是谁但不够格（重试无用）

### 3.3 响应中的 queryId（J4）+ 请求头指定 queryId（J11）

- JSON 通道：响应体含 `"queryId": "q…"`（服务端生成为 uuid v7，时间有序）
- IPC 通道（`format=ipc`，`application/vnd.apache.arrow.stream`）**及所有已注册
  查询的响应（含失败 / 超时 / 取消）**：响应头 `x-qsdb-query-id`
- **Flight 通道**（`--flight-bind`）：请求 metadata `x-qsdb-query-id` 同语义；
  `do_get` 在**响应 metadata** 回显实际使用的 id
- 用途：配合 `POST /api/v1/queries/{id}/cancel` 实现 JDBC `Statement.cancel()`

> **Flight 也进同一张注册表（2026-10-12 起）**：`do_get` / `get_flight_info` /
> `get_schema` 均按 HTTP 面同语义注册——受并发闸约束、可被 `/queries/{id}/cancel`
> 取消。此前 Flight 查询**完全不可取消**（游离 ctx），且 `do_get` 走 benign ctx
> 绕过了超时/内存闸。

**J11：客户端可在执行前指定 id** —— `POST /api/v1/query` 请求头
`X-QSDB-Query-Id: <客户端生成的 uuid>`。J4 之后 id 只在**响应时**才透出，
执行中的请求无法预知自己的 id，驱动只能按 SQL 文本反查运行中查询——
**同 SQL 并发（连接池下常见）会一并取消**，含其它连接的同语句。

| 情形 | 内核行为 |
|---|---|
| 合法且未被占用 | **原样采用**（不加前缀，驱动可直接按自己发出的值匹配） |
| 合法但已被**运行中**查询占用 | **回退服务端生成**——不报错、不顶掉在跑的那条；驱动以响应回显为准 |
| 非法（空 / 超 64 字符 / 含 `[A-Za-z0-9._:-]` 之外字符 / 非 UTF-8） | **400 `INVALID_ARGUMENT`**（不静默忽略） |

- 校验是为了不让 id 成为日志 / 指标 / 注册表 key 的注入载体；上限 64 字符足以
  容纳 UUID / ULID / KSUID / 驱动自有前缀
- 采用后 `GET /api/v1/queries` 的 `id` 字段与 `/queries/{id}/cancel` 均以该 id 为键
- **客户端应始终以响应回显的 id 为准**：冲突回退时它与请求值不同（响应头与
  JSON 体的 `queryId` 都会给出实际值）

### 3.5 请求严格化（2026-10-12 起）——**不做静默兜底**

拼错就报错。静默兜底是 J6 那类事故（参数拼错 → 悄悄退化成 N+1）的根因：

| 情形 | 行为 |
|---|---|
| body 含未知字段（`{"sql":…,"formatt":"ipc"}`） | 400 `INVALID_ARGUMENT`（此前静默忽略键） |
| `format` 非 `json`/`ipc`/`bulk`/`rows`/`csv` | 400 `INVALID_ARGUMENT`（此前静默按 JSON） |
| 行式 `rows` 的写侧 payload 带列描述（`flags` bit0 = 1） | 400 `INVALID_ARGUMENT`——写侧 schema 由 `table=` 决定，payload 里再放一份就是两个真相源（见 [rows-format](rows-format.md) §四） |
| `mode` 非 `append`/`overwrite` | 400 `INVALID_ARGUMENT`（此前静默按 append） |
| `expected_generation` 用于 append / 命中多分区 | 400 `INVALID_ARGUMENT`（CAS 是单分区语义——别挑一个分区用，宁可报错） |
| `withSchema` 非 `1/0/true/false/yes/no/on/off`（裸传 `?withSchema` = true） | 400 `INVALID_ARGUMENT`（此前静默当 false） |
| `PUT /api/v1/config` 键名不认识 | 200 但 `applied:false`（不再谎报成功） |

### 3.4 JSON 值形态（J1/J2/J7）——**按列类型分派，不做数值启发**

消费方**可以信任值形态与列类型一致**：

| Arrow 类型 | JSON |
|---|---|
| Int8..64 | number（i64 内恒精确） |
| Float32/64 | number；**NaN → `"NaN"`、±Inf → `"Infinity"`/`"-Infinity"`**（固定拼写） |
| Decimal128 | **字符串**（按 scale 精确，无 f64 中转精度损失） |
| Utf8 | **恒 string**（`'123'` 输出 `"123"`，不因内容是数字而改写为 number） |
| Boolean | true/false |
| Date32 | `"YYYY-MM-DD"` |
| Time64(ns) | `"HH:MM:SS[.fffffffff]"` |
| Timestamp | ISO 形态（`T` 分隔；带 tz 补 `Z`） |
| **Binary** | **小写 hex 字符串**（可逆；此前经数字启发被当十进制解析→字节换血） |

**另外**：SQL 小数字面量物化为 `Decimal128` 而非 `Float64`（`SELECT 1.5` 的 schema
是 `Decimal128(2,1)`）——精确语义合理，但按「浮点字面量→浮点列」直觉预期会落空，
需要浮点时显式 `CAST(1.5 AS DOUBLE)`。

### 3.6 SQL 能力登记：`INSERT … SELECT` + `read_csv`（2026-10-13，导入工具对接面）

两条**查询面原语**（内核只补原语，搬运工具由独立项目做）。经
`POST /api/v1/query`（或嵌入 API `db.sql`）使用，与其它语句同权限模型
（`INSERT` = Writer 及以上）。

**① `INSERT INTO t [(cols)] SELECT …`**——把任意查询结果写进管理表：

```sql
-- 从数据湖 parquet 灌进管理表（此前这条路直接 not supported）
INSERT INTO events
SELECT tenant, amount, score FROM read_parquet('s3://bucket/dt=2026-10-12/*.parquet');

-- 带列清单（位置语义：源第 i 列 → 清单第 i 个名字）
INSERT INTO t (b, a) SELECT x, y FROM s;

-- 部分列清单：未列出的列补 NULL（NOT NULL/CHECK 仍由写入端强制）
INSERT INTO t (a, c) SELECT a, c FROM s;
INSERT INTO t (a, c) VALUES (1, 3);   -- VALUES 源同样允许部分列（2026-10-13 放宽）

-- INSERT OVERWRITE：分区级原子替换（谓词命中的分区整体换掉，其余分区不动）
INSERT OVERWRITE events SELECT * FROM read_parquet('…') WHERE dt = DATE '2026-10-12';
```

| 契约 | 说明 |
|---|---|
| 列清单语义 | **位置对齐**（标准 SQL），非按名匹配；未知列/重复列报 `COLUMN_NOT_FOUND`/400 |
| 列数不匹配 | 400 `INVALID_ARGUMENT`（SELECT 输出列数 ≠ 列清单宽度，读取首行前就拒） |
| 类型校验 | `cast_rule` 矩阵：`Impossible`（如 BOOLEAN→BIGINT）400；可转换类型按值 cast；**转不动时报错，不写 NULL** |
| 分区表 | 按分区列值自动路由（append 语义）；`OVERWRITE` 只替换谓词命中的分区 |
| 回执 | `SqlResult::Ok { message, rows_affected, command }`——**结构化字段（J12）**：`command`（`INSERT`/`DELETE`…）+ `rows_affected`（DML 行数；DDL 为 `None`）。HTTP 响应同名字段 `command`/`rowsAffected`（仅在有意义时出现）。`message` 是**给人看的文案**（"文案不做兼容承诺"），驱动请读结构化字段 |
| **边界** | 列清单不覆盖全表时省略列补 NULL（**VALUES 与 SELECT 两条源一致**——此前 VALUES 要求列清单覆盖全表，2026-10-13 放宽，qsdb-jdbc 实测撞到）；SELECT 返回 0 行时 `OVERWRITE` 是**无操作**（不会清空分区）；源与目标同表时按计划期文件快照读取（非事务快照语义） |

**② `read_csv('路径')`**——CSV 文件当表查（`FROM` 子句表函数）：

```sql
SELECT tenant, sum(amount) FROM read_csv('exports/*.csv') WHERE dt = '2026-10-12' GROUP BY tenant;
```

| 契约 | 说明 |
|---|---|
| 解析 | RFC4180 子集：引号包裹字段（内含分隔符/换行/`""` 转义）、CRLF 与 LF、UTF-8 BOM、空行跳过 |
| 表头 | **首行必须是表头**（列名 = 绑定依据）；空列名报错 |
| 类型推断 | 扫前 1000 行判 int64 / float64 / boolean / utf8（拿不准回落 utf8；全空列 → utf8）；**推断结果全批稳定**，第 1001 行起的冲突值报错（不静默改类型、不静默 NULL） |
| NULL | 空字段 → NULL（含显式 `""`，与 DuckDB 默认 `nullstr=''` 同口径） |
| 路径 | 本地路径与 glob（`*` 段内 / `**` 跨段），与 `read_parquet` 同一套定位逻辑 |
| 列裁剪 | 有（计划级投影下推，未选列不做类型解析与数组构建） |
| 错误 | 文件不存在 = `file_not_found`（404）；表头/行宽/脏值 = 400，报错带文件名+记录号+列名 |
| **边界（不支持，报错明说）** | `s3://`/HDFS 远端（顺序流，无 range/footer 可省；先落本地）；压缩文件（.gz 等）；`HEADER=false`；自定义分隔符/引号/nullstr；**谓词下推到扫描内**（无 footer/RG 元数据可裁，谓词留在 FilterExec）；hive 目录分区推断；同一 glob 下要求文件**同构**（同表头/列序/类型域） |

## 四、行为契约

1. **只读模式**（`QsdbOptions.read_only`）：写/DDL/compact/gc 全拒——
   内核错误为 `QsdbError::ReadOnly`（文案含 "read-only"），HTTP 面 → 503
   **`READ_ONLY`**（**永不重试**：只读库对读完全可用，重试毫无意义，换实例才对）。
   standby/只读副本标准姿势。
2. **Durability 两档**：默认 ProcessCrash（kill -9 安全）；PowerLoss
   （fsync 掉电安全，吞吐 -25%）。工具侧无需关心，仅部署参数。
3. **可见性**：append/overwrite 返回即对后续查询可见（manifest 已提交）；
   staging 模式例外（flush 前不可见，文档化语义）。
4. **写幂等性边界**：append 非幂等（重试可能重复入段）——工具要 exactly-once
   请用 overwrite_partition 或自身位点管理（参考 qsdb-sync 设计 §十）。
5. **Schema 演进**：ALTER ADD COLUMN 后旧段可读（缺列补 NULL）；
   前缀兼容规则见 format-spec §7.1。删列/改型不支持——工具侧 check 报告。

## 五、版本与兼容承诺

- 表格式：**字段结构**冻结（见 §一）；manifest 的**格式版本**可演进，规则是
  「**尾部追加字段 = 同时 bump `version`**」，且**内核保证旧版本仍可读**。
  ⚠️ 别信 `serde(default)` 能兜底（postcard 不自描述）——见 §一.1 与 `format-spec.md` §7。
- 嵌入 API：semver——minor 只加不改，major 可改（提前一版 deprecate 注记）
- HTTP/Flight 契约：端点只加不改不删；字段只加（消费方须容忍新增字段）
- 升级路径：QSDB 版本升级**不要求工具做数据迁移**（内核读旧格式）；
  但**自己解析 manifest 字节的工具**必须接受新增的版本号（当前 v1/v2 都要接）

## 六、给 qsdb-sync 团队的最小对接清单

1. 读：`partition_stats`（或 HTTP detail）判增量 → 拷新 segment → 应用 manifest
2. 写：嵌入 `append` / `overwrite_partition`（或 HTTP write）+ `_sync.checkpoints` 普通表存位点
3. 协商：`sql("SELECT … LIMIT 0")` 取 schema 比对（`qsdb-sync check`）
4. 详细协议：`docs/主备与qsdb-sync设计.md`（复制协议 §3 / 语义 §十）
