# 超越 DuckDB 路线（目标：本地分析库，查询与写入都要拉开差距）

> 定位（用户定案）：**对手只有 DuckDB**。PG 那轮对照只是用来回答"81s 正不正常"
> （同一台机上 PG 同样形状也要 49s），不作为对标基线。
>
> 一切结论必须**有实测支撑**：`crates/qsdb-bench/src/bin/bench_suite.rs`
> （`--max-seconds` 闸门）+ `/root/bench/duckdb`（CLI 1.1.3，读同一份源文件）。
> 数字见 `docs/真机基准对账.md`。

**最近更新：2026-10-13**

## 一、先认清：我们赢在哪、输在哪（5M 行实测）

| 用例 | 我们 | DuckDB | 相对 | 性质 |
|---|---|---|---|---|
| simple_count | 0.001s | 0.021s | **赢 20×** | 少干活（元数据短路） |
| simple_topn | 0.033s | 0.041s | **赢 1.2×** | 少干活（有界 TopN，不全排） |
| simple_distinct | 0.032s | 0.223s | **赢 7×** | 少干活（只算个数） |
| simple_filter | 0.048s | 0.041s | 持平 | 都用向量化过滤 |
| simple_group | 0.204s | 0.183s | 1.11× | 并行聚合（已有） |
| complex_cte | 0.167s | 0.122s | 1.4× | |
| complex_window | 0.096s | 0.041s | **2.3×** | 整分区物化 + 单线程 |
| **complex_join_group** | 0.693s | 0.122s | **5.7×** | 探测逐行 + build 单线程 |
| import_parquet | 2.06s | 1.78s | 1.16× | 写段单线程 |
| **import_csv** | 5.44s | 3.11s | **1.75×** | **CSV 解析单线程**（解析本身 3.0s） |
| **export_parquet** | 2.96s | 0.87s | **3.4×** | **写单线程 zstd**（扫描已并行） |
| **export_csv** | 4.14s | 0.89s | **4.6×** | 格式化 + 写单线程 |

**规律（一句话）**：**我们赢在"少干活"，输在"要干活但只用一个核"。**
DuckDB 是 morsel 驱动的**全算子并行**流水线；我们除"并行聚合""并行扫描（刚补）"
之外，**算子与写路径都是单线程串行**——在 16 核上天然让出 ~10× 的吞吐。

所以"超过 DuckDB"的主线不是调参数，而是**把并行补齐，并继续扩大"少干活"的优势**。

## 二、Program（按杠杆排序，每步都用闸门复测）

### P0 并行（结构性，收益最大）

| # | 项 | 现状 | 目标 |
|---|---|---|---|
| ① | **并行扫描** | ✅ 已落地（公开 `scan` API 透明并行；`QSDB_SCAN_SERIAL=1` 可关） | 导出 3.48→2.96s |
| ② | **并行写段** | 段编码（parquet+zstd）单线程 —— **现在是导出/导入的共同天花板** | 多 row-group 并行编码；导出 → ~1s 量级 |
| ③ | **并行 join** | build 单线程建索引；probe 逐行 | build 分区并行 + probe 分片并行 |
| ④ | **并行 window** | 整分区物化 + 单线程 | 分区级并行（分区之间天然独立） |
| ⑤ | **并行 sort/归并** | `RunMerger` k 路归并单线程 | 并行排序 + 并行归并 |

### P1 算子内核（算法层面）

| # | 项 | 现状 | 备注 |
|---|---|---|---|
| ⑥ | join 探测批量化 | 逐行 probe（每行哈希 + 查表） | DuckDB 是批量 probe + 输出批 |
| ⑦ | window 流式帧 | 整分区物化 | 有序输入下可流式累积 |
| ⑧ | **CSV 解析并行** | 单线程（5M 行 3.0s） | 按字节段切分 + 段内独立解析；**import_csv 的 1.75× 全在这** |
| ⑨ | `VALUES` 快路径 | 每格一个 `Literal` 再翻成数组（12ms/1000 行） | 直接从 AST 值构造列式数组 |

### P2 把"少干活"的优势再扩大（我们已赢的领域）

- 元数据短路继续下沉：`min/max` 也能走 parquet 统计（现在只有 `count(*)`）；
- zone map 用到 row-group 级（更狠的跳过）；
- 聚合下推（HAVING/limit 提前停）；
- 有界 TopN 已经赢了，继续把 `ORDER BY … LIMIT` 的路径做透（TopN 与聚合、TopN 与 join）。

## 三、纪律（避免又变成"感觉不对"）

1. **每次改动必须过闸门**：`bench_suite --all --max-seconds 10` 全绿 + DuckDB 对照表。
2. **对照必须同数据同形状**，且写明口径（缓存/并行度/压缩档）。
3. **不达标就是没做完**——"和 PG 同量级"不是理由（PG 不在对标范围内）。
4. 数字落 `docs/真机基准对账.md`，结论落本文档；**每次改动的收益都要能被复现**。
