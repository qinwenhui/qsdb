# 内核行为变更通知（给生态工具 / SDK）

> 版本：v1（2026-10-13）　适用内核：`68df15c`（闸门）之后，含 `0649bc9`（三条实现）
> 读者：qsdb-jdbc / qsdb-odbc / qsdb-sync 及任何消费 QSDB 的 SDK
> **一句话**：以前有一批 SQL 子句会**静默按"没写"执行**（不报错、给错结果）；
> 现在起**要么正确执行、要么报错**——`UNSUPPORTED`（HTTP 501 / `retry=no` / SQLState `0A000`）。
> 权威清单：**`docs/SQL支持面.md`**（内核仓），以后"这条能不能写"看它，不用试。

---

## 一、你必须动作的一条：这些写法现在会**报错**

如果你（或你的文档/示例/集成测试）写过下面任何一种，**以前它静默跑错、现在会拒**。
请改成建议列里的写法，或从测试里去掉——**别把它当回归**：

| 你写的 | 以前实际发生 | 现在的替代 |
|---|---|---|
| `count(DISTINCT x)` / `sum(DISTINCT x)` | **回错数字**（当成 `count(x)`） | `SELECT count(*) FROM (SELECT DISTINCT x FROM t)` |
| `count(*) FILTER (WHERE …)` | **回错数字**（当成 `count(*)`） | `count(CASE WHEN … THEN 1 END)` |
| `… OVER (ORDER BY y ROWS BETWEEN …)` | **回错数字**（用默认累计帧） | 去掉帧子句（默认帧 = 累计），或自行改写 |
| `INSERT … ON CONFLICT DO NOTHING` | **插入了重复行** | 先查后插；或用 `INSERT OVERWRITE` 整分区替换 |
| `LIMIT n OFFSET m` / `OFFSET m ROWS` / `LIMIT m, n` | **丢掉 offset**（少翻页） | ✅ **已实现**（见 §二），照写即可 |
| `ORDER BY x NULLS FIRST/LAST` | **忽略**（恒用默认放置） | ✅ **已实现**（默认 `ASC⇒NULLS LAST`／`DESC⇒NULLS FIRST`） |
| `FETCH FIRST n ROWS ONLY` | **忽略**（返回全表） | ✅ **已实现**（等价 `LIMIT n`）；`PERCENT`/`WITH TIES` 仍拒 |
| `SELECT DISTINCT ON (a) …` | 当成普通 `DISTINCT`（**多返回行**） | 用窗口函数或 `GROUP BY` |
| `SELECT count(*) FROM t TABLESAMPLE (10 PERCENT)` | 当全表（多返回） | 去掉（未实现采样） |
| `SELECT * EXCLUDE (b) FROM t` | **静默返回全列**（含 b） | 显式列出需要的列 |
| `SELECT * FROM t EXCLUDE (b)` | ⚠️ 被解析成「别名 `exclude` + 列清单」⇒ **静默返回全列** | 同上 |
| `WITH w(q) AS (SELECT …) …` / `… AS d(x)` | 列别名被丢掉 → 之后报"列不存在"（误导） | 在子查询里 `SELECT a AS q` |
| `SELECT TOP 2 …` / `SELECT … INTO` / `QUALIFY` / `FOR UPDATE` | 静默忽略 | 用 `LIMIT` 等，或去掉 |
| `INSERT … RETURNING` / `IGNORE` / `REPLACE INTO` | 静默忽略 | — |

**自查建议**（在你仓里 grep 一遍就够）：`DISTINCT`、`FILTER`、`OFFSET`、`NULLS`、
`TABLESAMPLE`、`ON CONFLICT`、`EXCLUDE`、`FETCH`、`TOP `、`RETURNING`、`QUALIFY`。

## 二、新增能力（以前不可用或悄悄错的，现在对了）

1. **`OFFSET` 全套**：`LIMIT n OFFSET m`、`OFFSET m`（不带上界）、`LIMIT m, n`（MySQL 形）。
   → **BI 工具分页（DBeaver 等）可以直接用**。
2. **`FETCH FIRST n ROWS ONLY`** ≡ `LIMIT n`。
   ⚠️ `FETCH FIRST n PERCENT ROWS` 与 `… WITH TIES` 语义不同（按比例／含并列），
   **内核拒绝执行**——绝不当 `LIMIT` 处理。
3. **`ORDER BY … NULLS FIRST/LAST`**（含**窗口内** `ORDER BY`），规则与 PG 一致：
   默认 `ASC ⇒ NULLS LAST`、`DESC ⇒ NULLS FIRST`，显式值覆盖默认。
4. **`count(DISTINCT x)` 的等价改写**（唯一可用路径）：
   ```sql
   -- count(DISTINCT a) FROM t
   SELECT count(*) FROM (SELECT DISTINCT a FROM t);
   -- 带分组
   SELECT g, count(*) FROM (SELECT DISTINCT g, a FROM t) GROUP BY g;
   ```
   原生实现仍在排队（`docs/超越DuckDB路线.md` P1⑩）。

## 三、契约面的其它变化（可能影响你的解析/断言）

| 项 | 变化 | 对驱动的影响 |
|---|---|---|
| **空输入的无 `GROUP BY` 聚合** | 从"**零个批**"变成**恰好一行**（`count`→0 / `sum,avg,min,max`→NULL） | ✅ 以前 `SELECT count(a) FROM t WHERE <不匹配>` 在网线上是**空数组**，你的兜底逻辑可以撤了 |
| **零行结果** | 带**一个空批 + 完整 schema**；`format=ipc` 的**批数 0→1**（**行数仍 0**） | 若你按"没有批 = 无结果"判断，请改判**总行数 == 0** |
| **`#[non_exhaustive]`（Rust API）** | `SqlResult` / `QsdbError` / `WriteResult` / `CompactResult` / `PartitionStat` 已标 `#[non_exhaustive]` | 只有 Rust 嵌入方受影响：匹配需 `..` + 通配臂（一次性） |
| **DDL 收紧** | 分区表**至少要有一个非分区列**（`CREATE TABLE t (p BIGINT) PARTITIONED BY (p)` 现在拒） | 若 DDL 测试用了这种形状，加一列数据列 |
| **错误码** | 上述拒绝统一 `UNSUPPORTED`（501 / `retry=no` / `0A000`）；**不要重试**，改 SQL 才有用 | 码表可经 `GET /api/v1/error-codes` 运行期拉取 |

## 四、为什么不"保持兼容"

这些子句以前的行为**不是"不支持"，而是"静默给错结果"**——`count(DISTINCT)`
回的是 `count()` 的数、`FILTER` 回的是全量聚合、`ON CONFLICT` 真的插了重复行。
报错是**升级**：错值比报错危险得多（错值会被写进下游报表）。

我们为此加了一道**绑定前的闸门**（内核 `sql::translate` 的四个 `audit_*`），
**新增语法只有两条路：实现它，或在闸门里拒绝**——不存在第三条"静默忽略"。
每条拒绝都有回归测试（`crates/qsdb/tests/sql_silent_drop.rs`），
每条都配正例对照，防止一刀切把正常查询也拒了。

## 四之二、`manifest` 有了**格式版本号**（2026-10-14，v2）

| 项 | 内容 |
|---|---|
| 变更 | `manifest.postcard` 的 `version` 字段：新写入的是 **2**；`QsdbOptions`/HTTP 接口**一律不变** |
| 内核行为 | **v1 与 v2 都能读**（v1 尾部缺 `epoch`，内核补 `epoch = 0` 后解）；不认识的版本报**明确的版本错误** |
| 对你的影响 | **只有"自己解 postcard 字节"的工具**要注意：要么改用内核 API（`partition_stats` / `PartitionManifest::read`），要么**同时接受 version 1 与 2** |
| 数据要不要迁移 | **不要**。旧目录内核照读 |

**为什么会变**：F26 给 manifest 尾部加了 `epoch` 字段**却没升 version**，
于是"旧数据 + 新内核"报的是 `corrupt manifest … Hit the end of buffer`——
**它看起来像数据损坏，其实是版本不同**。根因是 postcard **不是自描述格式**：
`#[serde(default)]` 在它身上**一点用都没有**（只对 JSON 那类生效）。

> ⚠️ 如果你（或你的文档）里写过「manifest 加字段带 `serde(default)` 就向后兼容」——
> **那条是错的**，契约文档已更正（`docs/对接契约.md` §一.1 / §五、`docs/format-spec.md` §7）。
> 正确规则：**尾部追加字段 = 同时 bump `version`**，且读者要保留旧版本的读路径。

## 五、有异议/踩到了怎么办

- 若某条你认为**应该支持**（而不是拒）：按老规矩写反馈（qsdb-sync 走
  `docs/QSDB对接反馈.md`，jdbc/odbc 走各自 `内核反馈` 文档），标明**用量与场景**。
- 若某条你**写在 SDK 的 SQL 模板里**必须改：`OFFSET`/`NULLS`/`FETCH` 已实现可直接用，
  其余按 §一 的替代列改。
